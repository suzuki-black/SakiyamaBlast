# 相談書: もう一つのギミック — 連鎖の「段取り」を増やす

**別の人／AI に相談するための資料。** この1枚だけで話が通るように書いてあり、
ソースは読まなくてよい。数値はすべて **2026-10-18 時点のコードの実値**
（`tools/hostsim` の実測を含む）。

---

## 0. 相談したいこと

**連鎖に至るまでの「段取り」を増やすギミックを、もう一つ考えてほしい。**

いま段取りの軸は **「岩を横へ動かす」** と **「岩の落ち道をあらかじめ掘る」** の2本しかない。
15面しかないとはいえ、**仕組みが単純に見えてしまう**（作者の指摘、2026-10-18）。

### 大事な条件（ここを外した案は入らない）

> **手順が複雑に「見える」こと。実際に複雑にしてはいけない。**
> 本当に複雑にすると、増えるのは**とっつきにくさだけ**になる。

つまり狙いは「**1つ1つは一目で分かる操作**が、**何段か積み重なって見える**」状態。
**普通にクリアするだけなら難しくないまま**で、**連鎖を狙うときだけ段取りが要る**。
Dig Dug と同じで、**上手い遊び方のほうにだけ難しさを置く**。

### 答えてほしい形

案ごとに次を書いてほしい。**§5 の制約と §6 の教訓を外した案は入らない。**

1. **何が起きるか**（画面と音で。プレイヤーから見た描写）
2. **段取りがどう増えて見えるか**（手順を1つずつ並べて）
3. **なぜとっつきにくくならないか**（1手1手が自明である理由。知らなくてもクリアできる理由）
4. **既存のどの軸と組み合わさるか**（§3 の表）
5. **コスト**（新しい絵・升ごとの状態・コード量の見積り。§5.2 の空きと突き合わせて）
6. **測り方**（`tools/hostsim` で何を数えれば「効いている」と言えるか。§7）
7. **リスク**（詰みを作らないか、死因が増えないか、読めない事故にならないか）

## 1. ゲームの要点

- MSX2 以降（turbo R 推奨）の1画面固定アクション。SDCC で C、ASCII8 MegaROM（128KB）
- 炭鉱夫「丹野3時」（作者の祖父がモデル。名前はもじった架空名）を操作し、
  地層を掘って**黒ダイヤ（石炭）を全部採掘したらクリア**。全15面
- 盤面は **16列 × 11行 = 176升**（1升16×16px）。60fps
- 骨格は Dig Dug ＋ Mr. Do!（メカニクスのみ参考。絵・音・曲はオリジナル）
- 敵をよけ、上がり続ける**体温**を水風呂で冷ましながら掘る。1面の持ち時間は 2:20〜3:00
- **盤面は面ごとに固定**（乱数ではなく選んだ種で組む）。覚えて上達する対象

### 死因は4つだけ。増やさない

落ちてきた岩に潰される／敵に触れる／体温のオーバーヒート／時間切れ。

## 2. 連鎖の仕組み（本作の核。ここを壊す案は入らない）

- 黒ダイヤは**耐久**を持ち、つるはしで叩くと1ずつ減る。0で**割れた状態**になり、
  **その升は通れるようになる**（＝「掘った升」と同じ扱いになる）
- 割れた黒ダイヤの升に入ると、**繋がっている割れた黒ダイヤをすべて同時に採る**
- **落ちてくる岩は、割れた黒ダイヤを突き抜けて、その場で採掘する**
- **連鎖は時間で繋がる**（3秒）。岩が採ったぶんも自分で採ったぶんも同じ連鎖。
  得点は採った順に 200 → 400 → 800 … と倍々

### 岩が落ちる・止まる条件（段取りの土台）

| | |
|---|---|
| 落ちる | **真下の升が「掘った升」になった瞬間**（0.75秒揺れてから落ちる） |
| 止まる | **真下が土・未割の黒ダイヤ・別の岩・盤面の底**。鉱車の上も止まる |
| 通り抜ける | **掘った升と、割れた黒ダイヤ**。この2つだけ |
| 横へ | **自機が左右に押せる**（土の中へも押し込める）。**樋**に当たると隣の列へ1升逸れる |
| 全部落ちる | **炭柱**（耐久が高い特別な黒ダイヤ。面に2本）を割ると**盤面の岩が一斉に落ちる**＝落盤 |
| 消える | 一定の距離を落ちると割れて消える |

**自機が真下に居る間は岩は揺れも落ちもしない**（Dig Dug 準拠）。好きなだけ待てる。

## 3. いまある「段取りの手」

| 軸 | 何をするか | 入る面 | 1手の見た目 |
|---|---|---|---|
| **押す** | 岩を左右へ押して、黒ダイヤの真上へ揃える | 面2〜 | 歩いて押すだけ |
| **掘る** | **縦の鉱脈に挟んである土**を先に掘り、岩の落ち道を繋げる | 面2〜 | 横から入って掘るだけ |
| 樋（とい） | 板に当たった岩が隣の列へ1升逸れる（使い切り） | 面4〜 | 置いてある板を使うだけ |
| 鉱車 | レールの上を往復する鉱車に岩を載せ、車止めで放り出す | 面10〜 | 載せて待つだけ |
| 落盤 | 炭柱を割ると盤面の岩が一斉に落ちる | 全面 | 叩くだけ |
| 熱水 | 湧き出した熱水は岩で堰き止められる。敵は通れない | 面7〜 | 岩を置くだけ |

### 「掘る」の形（2026-10-17 に入れたばかり）

縦の鉱脈に**土を1升ずつ挟んで**置いてある。落ちる岩が通れるのは「掘った升」と
「割れた黒ダイヤ」だけなので、**隙間を先に掘っておかないと一段ぶんしか採れない**。

```
   .O.   岩           岩を支えているのは一番上の黒ダイヤなので、
   .4.   黒ダイヤ     そこを割った瞬間に落ちる。だから段取りは
   ...   ← 掘る       「下の段から割る → 隙間を掘る → 最後に一番上を割る」。
   .4.   黒ダイヤ     順番を間違えると一段で終わる。
   ...   ← 掘る
   .4.   黒ダイヤ
```

面ごとの深さ（実測）:

| 面 | 1 | 2〜3 | 4〜6 | 7〜9 | 10〜12 | 13〜15 |
|---|---|---|---|---|---|---|
| 仕込んだ鉱脈 | 0 | 1本 | 1本 | 1本 | **2本** | **2本** |
| 掘る升 | 0 | 1 | 2 | 3 | **5** | **6** |
| 掘った見返り（黒ダイヤ） | 0 | +1 | +2 | +3 | +5〜6 | **+6** |

**この2軸だけだと、面が進んでも「押す数が増える・掘る数が増える」しかない。**
そこが今回の相談の出発点。

## 4. 1面の遊びの流れ（段取りが要る遊び方）

1. 面番号の形に掘り抜かれた坑道に立っている。黒ダイヤは土の中に**縦の鉱脈**として埋まっている
2. 鉱脈へ掘り進み、**下の段から割る**（上から割ると岩が落ちて一段で終わる）
3. **挟まっている土を横から掘って**、岩の落ち道を繋げる
4. 岩が鉱脈の真上に無ければ**押して揃える**（樋や鉱車で横へ運ぶ面もある）
5. **最後に一番上を割る** → 岩が全段を貫き、連鎖が伸びる
6. 掘るほど体温が上がり、敵は早く透明化して土の中を突っ切ってくる（切羽圧）

## 5. 制約

### 5.1 遊びの制約

- **死因を増やさない**（§1）
- **詰ませない。** 資源を全部失っても進める道を残す
- **理不尽にしない。** 危険は必ず予兆を出す（例: 敵が透明化する1秒前から点滅する）
- **色は意味を持っている。** 敵の色＝アルゴリズム、黄枠＝炭柱。状態表示に色を使わない
- **知らなくてもクリアできること。** 新しいギミックが「分からないと進めない」になってはいけない

### 5.2 技術の制約（ここは本当に厳しい）

| | 空き |
|---|---|
| 常時見えるコード領域（固定領域 24KB） | **737バイト** |
| バンク窓（8KB。面の組み立てなど、タイトル画面から呼ばれないコードを置く） | **236バイト** |
| RAM 実行領域（9.25KB） | **100バイト** |
| **RAM の変数** | **91バイト** |
| ROM 全体（128KB。絵・曲・表はいくらでも足せる） | 潤沢 |

**ただし「RAM が足りない」のは作りの都合で、本質的な不足ではない。**
カートリッジから見える RAM はページ3の **16KB だけ**（0xC000-0xFFFF。ページ0はBIOS、
ページ1〜2はカートリッジのROM）。上端3.4KBはBIOSの作業領域なので、使えるのは約12.9KB。
**そのうち 9.25KB は自分のコードで埋めてある** — ROM の窓が32KBしかなく固定領域が
尽きたので、**コードの置き場を RAM で買った**。残り3.2KBが変数で、その約2.3KBが
**升ごとの配列**（176バイト×9本＋面の組み立て用の作業配列）。

取り戻す道は3つあり、どれも未着手:

| 手 | 取り戻せる量 | 代償 |
|---|---|---|
| **真偽値の配列を詰める**（`dug` `pillar` `powder` `ume` `bombdrop` は 0/1 しか入っていない） | **約770バイト** | 読み書きに数バイトのコードと、わずかな速度 |
| **窓をもう1枚増やす**（ASCII8 は 8KB の枠が4つ。いま3つを固定扱いにしている） | **最大8KB**（RAM実行をやめられる） | 切り替えの設計をやり直す |
| スロット切り替え / メモリマッパ | さらに大きい | BIOS のフォント参照など、影響が広い |

**つまり「升ごとの配列が1本要る」案を却下する必要はない。** 本当に良い仕掛けなら
770バイトは詰めれば出る。ただし**タダではない**ので、提案にはコストを書いてほしい。
いますぐ無料で使えるのは、既存の配列の空き値・空きビット:

- `dug[]`（0/1）… 7ビット空き
- `cell_link[]`（膜の有無。bit0/bit1 だけ使用）… **bit2 以上が空き**
- `coal[]`（0 / 1〜11 / 255=割れた）… **12〜254 が空き**
- `chute[]`（0 / 左 / 右）… 空き値あり
- `powder[]` `ume[]` `bombdrop[]`（それぞれ 0/1 で1バイト使用）… 詰めれば352バイト浮く

**コードは窓側へ逃がせる**（面の組み立ては常時見えている必要がない）。
絵・タイルはバンクへいくらでも足せるので制約にならない。

### 5.3 画面の制約

- 盤面は 16×11 升に固定。広げられない
- スプライトは**1走査線に8枚まで**。だから「1行に岩は1個まで」が盤面の必須条件
- 同時に出せる敵は6体
- ボトルネックは CPU ではなく **VDP への書き込み量**。毎フレーム塗り直す演出は fps に直結する

## 6. 過去の教訓（提案を選ぶ基準）

**演出を10項目積んでも作者の体感は変わらなかった。効いたのは3つだけで、
どれも「ルールを絵で説明していた」。**

1. 岩が黒ダイヤを突き抜けて採る
2. 連鎖が時間で繋がる
3. **かけらが自機へ集まる** — 「岩で鉱脈を割ると自分のものになる」を言葉でなく絵で説明している

**見た目の派手さではなく、仕掛けの説明になっている演出だけが効く。**
今回のギミックも同じ基準で見てほしい。**「何が何を引き起こすか」が画面で読めること。**

もう一つの教訓: **ルールが見えないと理不尽になる。** 出水（熱水）を入れたときも、
「どこから湧くか」を固定して絵を出すまでは事故にしか見えなかった。

## 7. 測り方（提案が効いているかの確認手段）

`src/` のゲームロジックを**そのまま gcc でビルド**し、VDP/PSG だけスタブに差し替えて
ヘッドレスで走らせる仕組みがある（`tools/hostsim`）。15面×24回で数秒。

いま盤面について測れるもの（抜粋）:

| 指標 | 意味 |
|---|---|
| `hand` | **つるはし1本入れるだけで採れる数**（掘らない・押さない）。段取り無しの取れ高 |
| `hpush` / `hprep` | 岩を1個／全部押して揃えてから採れる数。**押す軸の見返り** |
| `digpay` / `digcells` | **隙間を掘ったぶん増える数** / そのために掘る升の数。**掘る軸の見返り** |
| `par` | 邪魔されずに盤面を片付けたときの所要フレーム数 |
| `rowdup` | 1行に岩が2個以上ある行の数（**0が必須**。スプライトの制限） |

**新しい軸を足すなら、同じ形で「その手を打ったときの見返り」を測れる必要がある。**
種（盤面）は総当たりで選んでいるので、**測れない条件は盤面の必須条件にできない**。

## 8. こちらで考えた候補（叩き台。これを超える案がほしい）

### 候補A: 支柱（つっかい棒）★ 本命 → **2026-10-20 に実装した**

**岩の真下の坑道に立っている坑木。立っている間、岩は何があっても落ちない。**
つるはしで1回叩くと折れて、岩が落ちる。

```
   .O.      岩            いま      : 一番上の黒ダイヤを割った瞬間に落ちてしまう
   .4.      黒ダイヤ      支柱あり  : 割っても落ちない。支柱を折ったときに落ちる
   .|.  ←   支柱
```

- **段取りはこう見える**: 「鉱脈を上から下まで全部割る」→「隙間を掘る」→
  「岩を押して揃える」→ **最後に支柱を折る**。**引き金が独立した1手になる**
- **実際にはやさしくなる。** いまは「上から割ると岩が落ちて台無し」という
  **順番の罠**があるが、支柱があると**順番を気にせず準備できる**。
  見た目の手数は増えて、失敗の罠は減る（＝相談の条件そのもの）
- **複数の岩を同時に撃てる。** 支柱で止めた岩を何本か用意して、順に折れば連鎖が繋がる
- 史実: 坑内は坑木で枠を組んで支える。炭柱（残柱式）とも揃う
- コスト: 絵1枚（縦の坑木）。状態は **`cell_link[]` の空きビット**に入れられるので
  **RAM の新規消費ゼロ**。支え判定に1行、叩いたときの処理が十数行
- 測り方: 「支柱を折る前の取れ高」と「折ったあとの取れ高」の差（`proppay`）。
  既存の `digpay` と同じ作りで測れる
- リスク: **自機が支柱の真下に居るときに折ったら潰れる** → いまの「真下に居る間は落ちない」
  規則がそのまま効くので、**新しい死因にはならない**
- **実装済み（2026-10-20）。** 絵1枚（支柱に載った岩）＋岩ごとの1バイト。
  固定領域 +286バイト。残りの候補（B〜E）はまだ空いている

### 候補B: 吊り岩（遠い引き金）

支柱の発展形。**岩から数升離れた場所に立っている坑木**と岩を、画面に**梁の線**で結んで描く。
梁の端を叩くと、離れた岩が落ちる。

- 「ここを叩くと、あっちが落ちる」が線で見えるので、**盤面が仕掛けに見える**
- 段取りが**移動**を含むようになる（準備してから引き金のところまで走る）
- コスト: 梁の線を描くぶん絵と描画が増える。候補Aより重い
- リスク: 線の引き回しが盤面の見通しを悪くするかもしれない

### 候補C: ずり（瓦礫）

割れて消えた岩が**ずり**を残し、拾って**穴を1升埋められる**。岩の落ち先を
「止めたい場所で止める」ために使う。

- 段取りに「資源を集めて使う」が入る
- **実際に複雑になりすぎる**疑いが強い（在庫管理が増える）。条件に反する可能性

### 候補D: 転轍機（てんてつき）

鉱車のレールに分岐を置き、**自機が踏むと向きが変わる**。岩をどちらの車止めへ運ぶか選べる。

- 1手は「踏むだけ」で自明。鉱車のある面（面10〜）限定なのが弱い
- コスト: レールの分岐の絵とレール配置の作り直し

### 候補E: 炭層の目（もく）

鉱脈に向きがあり、**貫いた岩がその向きへ1列ずれて落ち続ける**。

- 樋と役割が被る。**向きが絵で読めないと理不尽**になりやすい
