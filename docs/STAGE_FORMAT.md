# sakiyama-stage 形式 仕様書 (formatVersion 1)

面1枚ぶんの盤面を1つの JSON にまとめるための形式。
**面エディタと数値化ツール (`metrics.py` / `emotion.py`) の受け渡しに使う。**

- 生成: `tools/hostsim/sim --stage N --dump`
- 読み込み: `tools/hostsim/sim --load <file>` / `metrics.py --load` / `emotion.py --load`
- 実装: `tools/hostsim/stagefile.c`（**ホスト側の道具だけ。ROM には入らない**）

> **ROM には何も足していない。** 盤面を決める変数はすべて `src/game.h` で公開されて
> いるので、読み込みはそこへ直接書くだけで足りる。ROM に面データを持たせるかどうかは
> まだ決めていない（生成のままにするか、手で作った面に置き換えるか。
> `docs/HOSTSIM.md`「未決の設計判断」）。決まるまでゲーム側は1バイトも増やさない。

---

## 0. 全体の構成

```
{
  "format": "sakiyama-stage",
  "formatVersion": 1,
  "generator": { ... },      // 何が作ったか（読み込みでは無視する）

  "stage": 7,                // 面番号。**盤面以外はこれが決める**（§5）
  "loop": 0,                 // 0=表面 1=裏面

  "dug":  [ 11行 ],          // 掘ってあるか
  "cell": [ 11行 ],          // 升の中身
  "over": [ 11行 ],          // 中身の上に乗るもの

  "start":  [c, r],          // 自機の出発点
  "nest":   [c, r],          // 敵の巣
  "bath":   [c, r],          // 水風呂（null = 無し）
  "spring": [c, r],          // 熱水の湧き出し口（null = 無し）
  "cart":   { "row": r, "from": c0, "to": c1 },   // 鉱車のレール（null = 無し）

  "gas":       [[c, r], ...],   // ガス（裏面）。最大4
  "rockOrder": [[c, r], ...],   // 岩の並び順。最大8
  "veins":     [[c, r], ...]    // 仕込んだ鉱脈の覚書。最大2
}
```

升は `[列, 行]` で、列は 0〜15、行は 0〜10（左上が `[0, 0]`）。

---

## 1. 板 — 1文字 = 1升

`dug` / `cell` / `over` はどれも **16文字の文字列を11本**並べた配列。
**3枚に分けてあるのが要点**で、1枚に詰めてはいけない（§1.4）。

### 1.1 `dug` — 掘ってあるか

| 文字 | 意味 |
|---|---|
| `.` | 土（未掘） |
| 空白 | 坑道（掘り済み） |

### 1.2 `cell` — 升の中身

**互いに排他。** 同じ升に2つ以上は置けない。

| 文字 | 意味 |
|---|---|
| 空白 | 何も無い |
| `1`〜`9` `A` `B` | 黒ダイヤ。耐久 1〜11（`A`=10, `B`=11。上限は `COAL_HP_MAX`） |
| `x` | 割れた黒ダイヤ（採掘待ち） |
| `O` | 岩 |
| `o` | 岩（**支柱で止めてある**。`rock_prop`。折る1手が引き金になる） |
| `>` | 樋。右下がりの板で、岩は**右へ**滑る（`CHUTE_R`） |
| `<` | 樋。左下がりの板で、岩は**左へ**滑る（`CHUTE_L`） |

> `\` を使わないのは、JSON の文字列でエスケープが要るため。
> 手で書くときに `\\` と書き損じる事故を避けている。

### 1.3 `over` — 中身の上に乗るもの

**互いに排他。** 置ける土台が決まっているものは、そうなっていないと読み込みが弾く。

| 文字 | 意味 | 土台 |
|---|---|---|
| 空白 | 何も無い | — |
| `*` | 炭柱（`CF_PILLAR`。割ると盤面の**すべての岩**が落ちる） | `cell` が黒ダイヤの升 |
| `p` | 火薬（ダイナマイトの弾薬。`CF_POWDER`） | `dug` が坑道の升 |
| `~` | 溜まり湯（`WATER_POOL`。最初から止まっている熱水） | `dug` が坑道の升 |

炭柱の耐久は `cell` の数字がそのまま効く（組み立て側は通常 +3 している）。

### 1.4 なぜ3枚なのか — 1文字に2つの意味を持たせて落ちた話

最初は `dug` と `cell` を1枚にまとめ、`O` が「土の中の岩」を兼ねる形で書いた。
**面10 でこれが崩れた。** `place_chutes()` は樋の落とし口の隣も掘るので、
**岩が居る升が掘り済みになる**ことがある。`O` の1文字では掘り済みを表せないので、
読み直すと升が1つ土に戻り、隣の膜（`LINK_RIGHT`）まで消えていた。

往復の検査（§6）が `dug_n=54` と `53` の差で見つけた。**手では気づけない。**

## 2. 一点物

| 項目 | 省略 | 決まり |
|---|---|---|
| `start` | 不可 | 坑道の升であること |
| `nest` | 不可 | 坑道の升であること |
| `bath` | `null` で無し | 坑道の升であること |
| `spring` | `null` で無し | 坑道の升であること |
| `cart` | `null` で無し | `row` の `from`〜`to` が全部坑道であること。`from <= to` |

---

## 3. 並び順のあるもの

### 3.1 `gas` — 裏面のガス

坑道の升に最大4つ（`GAS_MAX`）。**順が意味を持つ**（`gas_live(i)` が添字で引く）。

### 3.2 `rockOrder` — 岩の並び順

`cell` の `O` / `o` を**どの添字で持つか**。省略すると左上から読んだ順になる。

**省略してよいのは手で作った面だけ。** 生成した面では読む順と添字の順が違う
（面7 の実例: `[[13,1],[14,5],[14,7],[7,2],[15,3],[7,9]]`）。`rock_*` の配列は
添字で回すので、順が変われば当たりや落盤の見え方が変わりうる。

`cell` の岩と**個数が合わないか、同じ升が2回出ると弾く。** 支柱（`o`）は
`cell` 側が持っているので、ここには書かない。

### 3.3 `veins` — 仕込んだ鉱脈の覚書

**盤面には出ない。** `--analyse` が「下ごしらえが要る鉱脈を何本仕込んだか」を
言うのに使うだけ（`gapv_*`）。手で作った面には無くてよい。

---

## 4. 省略できるもの

| 項目 | 省略したとき |
|---|---|
| `format` / `formatVersion` | 検査しない（あれば値を検査する） |
| `generator` | 中身を見ない |
| `loop` | **`--ura` の指定がそのまま残る。** 0 に上書きはしない |
| `cell` / `over` | 全部空白 |
| `bath` / `spring` / `cart` | 無し |
| `gas` / `veins` | 空 |
| `rockOrder` | `cell` を左上から読んだ順 |

`stage` / `dug` / `start` / `nest` は省略できない。

**知らない項目は弾く。** 綴りを間違えた項目が黙って無視されると、
直したつもりの面が直っていないまま採点されるため。

---

## 5. 面データが決めないもの

**盤面だけが面ではない。** 次は `stage` と `loop` から引くので、面データで
上書きできない（したいときはゲーム側の表を直す）。

| もの | 置き場 |
|---|---|
| 敵の数・速さ・種類 | `src/levels.c` の難易度表 |
| 持ち時間 | `src/tlimit.c` の `tlimit_tbl[]` |
| 土の色（幕ごと） | `set_dirt_palette()` |
| 幕・番方の見出し | `STAGE_ACT()` / `STAGE_SHIFT()` |

つまり **`"stage": 7` と書けば「面7として」採点される。**
盤面を面1のものに差し替えても、敵は面7の強さで出る。

## 6. 往復の検査

```sh
sh tools/hostsim/roundtrip.sh
make roundtrip
```

面1〜15を表と裏で組み立て、書き出して読み直し、次の2つを見る。

1. **`--state` が組み立て直後と一致するか** = 面データが盤面を言い尽くせているか
2. **もう一度書き出した面データが元と一致するか** = 読み書きが対称か

`--state` は盤面を決める変数を**全部**並べて出す（`cflag` / `coal` / `chute` /
`water` / 岩8個 / 一点物 / `gas` / `veins` / 導出した数）。
**1 が落ちたら形式に取りこぼしがある。** 変数を足したのに `stagefile.c` を
直していない、という見落としがここで出る。

書き出し側にも検査が入っていて、**面データで表せない盤面はその場で止まる**
（1つの升に岩と黒ダイヤが同居している、樋が折れている、岩が升の境目に無い、
`over` が重なっている、など）。「書けたが読めない」を作らないため。

## 7. 使い方の例

### 生成した面を書き出して、手で直して、採点する

```sh
make hostsim
tools/hostsim/sim --stage 1 --dump > s1.json
# s1.json の cell を編集する
python3 tools/hostsim/metrics.py --load s1.json --runs 24
python3 tools/hostsim/emotion.py --load s1.json --runs 16
```

面1 の炭層の真上から岩を1個取るだけで、採点はこう動く（12回／面）。

| | クリア率 | ヒヤリ/分 | 放出 | 体温 | 判定 |
|---|---|---|---|---|---|
| 元のまま | 1.0 | 0.0 | 162 | 52 | NG: 緊張感不足 |
| 岩を1個取った | 0.0 | 6.53 | 13 | 158 | NG: 爽快率不足 |

**岩が1個の有無で「易しすぎる」が「クリアできない」へ振れる。**
面を手で作るなら、置くたびにこれを回すこと。

### 盤面を目で見る

```sh
tools/hostsim/sim --load s1.json --board      # ASCII で盤面を出す
tools/hostsim/sim --load s1.json --analyse    # 連鎖・岩の効き方を測る
```

`--load` は `--sweep` / `--water` / `--cart` とは併せられない（どれも自分で
盤面を組み直すので、読んだ盤面が消える）。

## 8. 面エディタ側への申し送り

- **読み書きは `tools/hostsim/sim` に任せられる。** エディタは JSON を書くだけでよく、
  盤面の整合はここの検査が見る（弾かれた理由は行番号付きで stderr に出る）。
- **置いた直後に採点を回せる。** `metrics.py --load --json` が指標と合否を JSON で返す。
- **`stage` を必ず書くこと。** 敵の強さと持ち時間がこれで決まる（§5）。
- **`rockOrder` は省略してよい。** 手で作る面に「生成側の添字の順」は無い。
- **`veins` は書かなくてよい。** 下ごしらえの覚書で、採点には効かない。
