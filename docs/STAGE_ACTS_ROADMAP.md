`CONSULT_PLAYFULNESS.md` の相談から出た結論。
**15面を5幕×3面に割り、幕ごとに動くものを1種類ずつ増やす。**

Mr. Do! Wild Ride / カンガルー / ドンキーコングの「面が進むとギミックが増える」構造を、
固定画面のパズルアクションに持ち込む。

**一つずつ実装してテストプレイし、効かなければその増分だけ捨てる**進め方を前提に書いてある。

---

## 0. なぜこれが効くと考えるか

### 本作には、時間で変わるものが体温しかない

盤面は自分が掘る以外に何も動かない。
Kangaroo も Wild Ride も、面ごとに**勝手に動くもの**が1種類ずつ増えていく。

そして `GAME_RULES.md` §2.11 の表を見ると、**15面の違いは数値と「ずらした岩の数」だけ。**
骨格が完成しているぶん、ここが一番の伸びしろ。

### 設計の基準（全増分に適用）

過去の教訓（`CONSULT_PLAYFULNESS.md` §0）をそのまま使う。

1. **仕掛けの説明になっているか。** 見た目の派手さではなく、規則を絵で説明しているか
2. **落とす前に、盤面を見るだけで結果を指でなぞれるか**
3. **読めない死因を作らないか**（`GAME_RULES.md` §8 の却下理由の筆頭）
4. **既存の規則で説明が付くか。** 新しい規則を足すより、既存の規則の応用にする

**「新しい死因を作らない」が特に重い。** 各ギミックがこれを満たすかを個別に判定してある。

## 1. 構造 ── 5幕×3面

### 幕＝坑の深さ、面＝番方

`GAME_RULES.md` §6 の未使用素材を2つ同時に使う。

| 軸 | 史実 | ゲームでの表示 |
|---|---|---|
| **幕（3面ごと）** | 常磐の炭層は海側へ7〜10度傾斜し、**深くなるほど条件が悪化**した | 第一坑〜第五坑。**土の色が深くなる** |
| **面（1面ごと）** | **3交代で24時間動いた**（一番方・二番方・三番方） | 面の開始に「一番方」「二番方」「三番方」を循環表示 |

```
第一坑 一番方（面1）  第一坑 二番方（面2）  第一坑 三番方（面3）
第二坑 一番方（面4）  ...
```

**3面で1日が回り、3日ごとに坑が深くなる。** 15面で5つの坑を降りる。

### パレットは2軸とも無料

- **幕** → 土の色（現在は3面ごとに茶・灰・青。**これを5段階に割り直す**）
- **番方** → 坑外の時間帯を HUD の枠や照明の色味に（朝・昼・夜）

`CONSULT_PLAYFULNESS.md` §5 の通り**パレット操作はほぼ無料**なので、
**幕の切り分けだけなら実質ゼロコストで先に入る。**

### 幕ごとに増えるもの

| 幕 | 面 | 増えるギミック | 実装 |
|---|---|---|---|
| **第一坑** | 1〜3 | ― （掘る・岩・炭柱・落盤） | **済** |
| **第二坑** | 4〜6 | **樋（とい）** | **済**（面1〜3から外すだけ） |
| **第三坑** | 7〜9 | **出水（熱水）** | 新規 |
| **第四坑** | 10〜12 | **鉱車** | 新規 |
| **第五坑** | 13〜15 | **ガス**（対案: 後山） | 新規 |

**新規実装は3つだけ。** 第二坑は既存の樋を面1〜3から外すだけで幕になる。

### 難易度カーブの作り直しが要る

`GAME_RULES.md` §2.11 の数値カーブは面番号に対して連続的に上がる作り。
**幕の頭（面4・7・10・13）で新しいギミックが入るぶん、数値のほうは一度緩める。**

```
      敵の数・耐久・透明化までの時間
      ↑
      │    ／│  ／│  ／│  ／│
      │  ／  │／  │／  │／  │     ← 幕の頭で一度下げ、幕の中で上げる
      └──────────────────→ 面
        1-3  4-6 7-9 10-12 13-15
```

`tools/hostsim` で測れる部分。**幕の頭の面は、その幕のギミックを覚える面にする。**

## 3. 第二坑（面4〜6）── 樋

**実装済み。** 面4で初めて盤面に樋が現れる。

### なぜ幕として成立するか

樋は**岩が横へ動く唯一の手段**（`GAME_RULES.md` §2.6）。
第一坑では「岩は真下にしか落ちない」で完結しているので、
**面4で初めて「横に曲がる」という概念が入る。**

### やること

- 面1〜3の種から樋を除いて選び直す
- 面4の開始時、樋を目立つ位置（自機の初手で使える場所）に置く
- **面4は樋の教材にする。** 面1が岩の教材であるのと同じ設計

### コスト

**ゼロ。** 種の選び直しと、幕の表示だけ。

## 4. 第三坑（面7〜9）── 出水（熱水）

### 史実

常磐は**石炭1トンに40トンの湯**が湧き、当時世界最大級の排水ポンプを並べていた。
**坑内水は温泉なので熱い**（気温40度・湿度100%）。

### 規則

```
炭柱を割ると、落盤と同時に、盤面のどこか1升から熱水が湧き出す
熱水は 1秒に1升ずつ、繋がった坑道を、下を優先して広がる
熱水の升に居る間、体温が毎フレーム +2（通常は15フレームで+1 なので30倍）
熱水の升は掘れない
敵は熱水に入らない
落ちてきた岩は熱水を止める（塞いだ升から先へは行かない）
黒ダイヤの採掘は妨げない（熱いだけ）
```

### 新しい死因を作らない（最重要）

**既存の体温メーターとオーバーヒートをそのまま使う。**
プレイヤーが覚える死因は1つも増えない。

そして**「なぜ水風呂が要るのか」の説明**にもなる。

### なぜ面白いか

**落盤の後が消化試合になっているのを解決する。**

```
いま      炭柱を割る → 大連鎖 → 残りを拾って終わり
出水後    炭柱を割る → 大連鎖 → 水が湧く → 残りを採りながら逃げる
```

**面の終盤に第二の山ができる。**

そして**自分が掘った坑道を通ってくる**のが効く。掘るほど水が回る。
`GAME_RULES.md` §2.7 の切羽圧（掘るほど敵が早く透明化する）とまったく同じ主題で、
**本作の芯を水でもう一度言い直すことになる。**

**敵が入らない**のが良い二面性を作る。熱いが安全。
追われているとき、水に一瞬逃げ込むという判断が生まれる。

**岩で塞げる**のは岩の新しい使い道だが、既存の「岩は落ちて止まる」だけで説明が付く。
**規則は増えない。**

### 詰み回避

**水は通行と体温にだけ効かせ、採掘は妨げない。**
水で黒ダイヤが採れなくなると面が詰むため。

### コスト

| | |
|---|---|
| 状態 | 176升 × 1ビット ＝ **22バイト** |
| 描画 | **毎秒1升だけ。** 背景タイル1枚の転送。安い |
| 絵 | 水の升のタイル1枚 |
| 演出 | パレットで水面を揺らす（無料）／湧き出しの音／広がる音 |
| コード | 広がりは `cell_link` の幅優先探索。**敵の経路計算が流用できるはず** |

**毎秒1升という速さが要。** これより速いと VRAM を食い、読めなくなる。

### テスト項目

- [ ] 落盤 → 出水 → 逃げる、の流れが「第二の山」として成立しているか
- [ ] 水に追われて詰む面が出ないか（`hostsim` で全面クリア可能性を確認）
- [ ] 敵が入らないことを利用した避難が成立するか
- [ ] 岩で塞ぐ操作が実際に使われるか（使われないなら水の速さか岩の位置の問題）
- [ ] 毎秒1升の描画で 55fps を維持できるか

### 未確認

- **湧き出す升をどこにするか。** 固定（種で決める）か、炭柱の位置から決めるか。
  **固定にして盤面に湧き出し口の絵を出しておく**ほうが読める可能性が高い
- 熱水か冷水か。**史実は熱水**だが、遊びとしては冷水（体温は下がるが動けない）もありうる。
  **熱水を推奨**（死因が増えないため）だが、体感で決める余地がある

## 5. 第四坑（面10〜12）── 鉱車

### 史実

`GAME_RULES.md` §6 の **ヒコーキ**（車両が歯止めを失って逸走すること）が由来。
坑内の運搬はレールと鉱車で行われた。

### 役割は「岩を水平に運ぶ装置」

樋は岩を横へ**1升**動かす。鉱車は**数升**動かす。
同じ横移動でも、距離と、**拍を待つ必要がある**点が違う。

### 規則

```
レールは面の開始時から盤面に描かれている（水平に4〜6升、背景タイル）
鉱車はその上を一定速度で往復する
岩が鉱車の上に落ちると、一緒に運ばれる
レールの端まで来ると鉱車は向きを変え、岩はそこで放り出されて落ちる
鉱車の升は塞がっている扱い（岩の支えになる）
自機が轢かれるとミス
敵が轢かれると倒せる
```

### なぜ読めるか

**落ちる場所が固定されている。** レールの端は面の開始から見えていて動かない。
だから**岩をどこへ届けられるかは、掘る前から分かる。**

プレイヤーが判断するのは「いつ落とすか」だけ。
鉱車は等速で往復するので、**メトロノームとして読める。**

### なぜ面白いか

**本作に初めて「待つ」が入る。**
いまの待ちは体温の上昇という罰の待ちだけだが、鉱車は**拍を数える待ち。**
しかも待っている間に敵が来るので、待つこと自体が賭けになる。

**動く支え**でもある。鉱車が下を通っている間だけ岩が支えられる配置が作れる。
既存の「支えが外れると落ちる」の応用で、**新しい規則はゼロ。**

### 懸念：新しい死因が1つ増える

**熱水と違い、これは避けられない。** `GAME_RULES.md` §8 の方針から一歩踏み出す。

読めない死因にならない根拠:

- レールは面の開始から見えている
- 鉱車は等速で往復し、加速も方向転換の予告も要らない
- 画面で一番大きく動くもの

**ここは判断が要る。** 不安なら、**轢かれると押される（岩と同じ扱い）**に留め、
壁に挟まれたときだけミスにする案もある（既存の岩の規則と一致する）。

### コスト

| | |
|---|---|
| スプライト | 鉱車1面（現在22/32面使用、10面空き） |
| 絵 | 鉱車1枚＋**「岩を載せた鉱車」1枚**（合体パターンで1面に収める） |
| 背景タイル | レール1枚（＋端の車止め1枚） |
| 状態 | 位置・向き・載っている岩の番号 |
| 音 | ガタンゴトンの走行音（PSG。低音の短い刻み） |

**「岩を載せた鉱車」を1枚の絵にするのが要。**
鉱車と岩を別スプライトにすると、その行のスプライトが2枚になり、
`GAME_RULES.md` の「1行に岩は1個まで」と競合する。

### テスト項目

- [ ] レールの行に他の岩を置かない配置で、横一列8枚制限に触れないか（実機で確認）
- [ ] 「いつ落とすか」の判断が成立しているか。往復が速すぎ／遅すぎないか
- [ ] 轢かれる死が理不尽に感じられないか。**感じるなら「押される」案へ切り替え**
- [ ] 鉱車で敵を倒す操作が使われるか
- [ ] 鉱車を「動く支え」として使う配置が面に入れられるか

### 未確認

- 往復の速さ。**自機の坑道内移動（60px/s）より遅くしないと逃げられない**
- レールを掘れるか。**掘れないほうが単純**（地形として読める）
- 岩が載ったまま鉱車が自機に当たったらどうなるか

## 6. 第五坑（面13〜15）── ガス（第一候補）

### 史実

`GAME_RULES.md` §6 の **カンテラ**と、いわき市史の事故一覧。
**ガス爆発が事故種別の最多**で、原因欄に「喫煙」「カンテラの灯」が繰り返し出る。

### 規則

```
行き止まりの坑道（長さ2升以上）にガスが溜まっていく
溜まるほど、その升の色が段階的に変わる（3段階）
ダイナマイトの爆風がガスの升に触れると誘爆し、連鎖して広がる
誘爆に自機が巻き込まれるとミス
坑道を掘り抜いて風を通すと（行き止まりでなくなると）ガスは抜ける
```

**「目抜（めぬき）」**＝接近した2本の坑道をつなぐ小坑道、という史実の用語がそのまま操作になる。

### なぜ面白いか

**ダイナマイトに初めて重さが出る。**
いまのダイナマイトは弾薬制で敵を倒すだけの道具だが、
ガスがあると**「どこで使えるか」を考える必要が出る。**

そして**掘り方そのものが問われる。** いまは最短で掘るのが最適だが、
行き止まりを作らない掘り方、風を通す掘り方という新しい技術が生まれる。
これも `cell_link` の応用で、**盤面の連結という本作の芯をもう一度使う。**

### 理不尽にしないための歯止め

- **自然発火はさせない。** 爆発するのは**プレイヤーがダイナマイトを使ったときだけ**。
  つまり**自分でやったことでしか死なない**
- ガスの濃さは**色で3段階はっきり見せる**
- 行き止まりの長さ1升では溜まらない（偶発的に作ってしまうため）

### コスト

| | |
|---|---|
| 状態 | 176升 × 2ビット ＝ **44バイト** |
| 描画 | **パレットで色味を変えるだけ。ほぼ無料** |
| コード | 行き止まり判定は `cell_link` の連結成分。出水と同じ仕組みが流用できる |
| 音 | 誘爆音（既存の爆発音の連打で代用できる） |

**パレットだけで可視化できるので、3つの新規ギミックの中で最も安い。**

### テスト項目

- [ ] ガスの色が「危険」として直感的に読めるか
- [ ] 行き止まりを作らない掘り方が実際に成立するか（盤面が窮屈すぎないか）
- [ ] ダイナマイトが使えない場面が多すぎないか
- [ ] 誘爆死が「自分のせい」と納得できるか

## 7. 第五坑の対案 ── 後山（あとやま）

**採らなかったが、記録しておく。**

### 中身

`GAME_RULES.md` §6 の **先山・後山**。先山は熟練の採炭夫、後山は運び手。
**夫婦や親子で組むことも多かった。**

採った石炭を運ぶ相棒NPCが付いてくる。最終幕で相棒が増える、という構成。

### なぜ強いか

**愛着という観点では最も強い。**
主人公は作者の祖父がモデルで、寡黙な人物として描かれている。
**最後の3面で一人ではなくなる**のは、題材として正しい終わり方になりうる。

### なぜ第一候補にしなかったか

- **守る対象が増えるとゲームの性格が変わる。** パズルから護衛に寄る
- 経路探索が要る（敵と同じ仕組みが使えるが、挙動の調整が別物）
- **ガスより明確に重い。** 15面の最後だけのために作る規模を超える

### いつ再検討するか

**ガスを入れてみて「機構は増えたが温度が足りない」と感じたら。**
そのときは第五坑ではなく、**エンディング側**で使うほうが安全かもしれない。

## 9. 制約とリスク

### ROM の空きが最大の制約

`CONSULT_PLAYFULNESS.md` §5 の通り、**固定領域 0x4000-0x9FFF の空きは153バイト。**

新規ギミックはどれも数百バイト要るので、**既存モジュールの RAM 実行への移送が前提**になる。
手順は確立済みとのことなので作業は読めるが、**増分0（幕の切り分け）を先に入れて、
コードの置き場を用意してから**ギミックに進むのが安全。

絵・タイル・曲は**バンクへいくらでも足せる**ので制約にならない。

### 幕ごとに難易度を一度緩める必要がある

§1 の通り。**新しいギミックを覚える面が、同時に一番難しい面になってはいけない。**

### 死因が増えるのは鉱車とガスだけ

| ギミック | 新しい死因 | 判定 |
|---|---|---|
| 樋 | なし | ○ |
| 出水 | **なし**（既存のオーバーヒート） | ○ |
| 鉱車 | **あり**（轢かれる） | △ 要判断。「押される」案あり |
| ガス | **あり**（誘爆） | △ ただし**自分でダイナマイトを使ったときだけ** |

### 3つのギミックが同時に画面に出る面（面13〜15）

**最終幕では、出水・鉱車・ガスが同時に存在する。**

- 熱水の升にガスは溜まるのか（**溜まらない**が自然）
- 鉱車は熱水の上を走れるのか（**走れる**が自然。レールは水に沈んでいる）
- 誘爆が鉱車を壊すのか（**壊さない**ほうが単純）

**この3つは面13を作る前に決めておくこと。**

## 付録: 相談で却下した候補

| 候補 | 理由 |
|---|---|
| **カンテラ（視界が狭まる）** | **却下。** 見えない＝読めない。設計基準に正面から反する |
| **相撲場（ボーナス面）** | **保留。** 幕の切れ目に入れると区切りとして機能し、ボーナスの弱さにも効く。ただし新しい画面を作る仕事なのでギミックとは別枠 |
| **山神様** | **保留。** ボーナス出現の演出として使う案。ギミックではない |
