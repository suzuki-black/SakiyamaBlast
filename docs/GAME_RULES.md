## 0. 一行で言うと

炭鉱夫「丹野3時」を操作し、**地層を掘って黒ダイヤ（石炭）に辿り着き、つるはしで
砕いて全部採掘する**。敵をよけ、体温の上昇を水風呂で冷ましながら進む。

---

## 1. 画面と盤面

| 項目 | 値 |
|---|---|
| 画面 | MSX2 SCREEN 5（256×212、16色） |
| 盤面 | 16列 × 11行 = **176升**（1升16×16px、上176px） |
| HUD | 下36px。**上段** スコア6桁／面番号／体温メーター16目盛り／連鎖数、**下段** 残機／ダイナマイト所持数／残り黒ダイヤ数／**残り時間** |
| フレームレート | 60fps |

面の開始時、**面番号の形に掘り抜かれた坑道**が置かれる（1〜15 の算用数字）。
数字の形なので**ばらばらの島に分かれる**ため、出発点・水風呂・湧き出し口が
届いていなければL字の通路を掘って繋ぐ。

## 3. 自機（丹野3時）

- **坑道内 60px/s、未掘の土を掘り進む間は 40px/s**（Dig Dug / Mr.Do! 準拠の減速）
- **方向転換は升の節点で**。半歩ずれていれば最寄りの節点へ寄せてから曲がる
- 掘り跡は**升の内側12×12px だけを抜く**。結果、隣り合う坑道の間に**薄い土の膜**が2px残る（§8）
- 向きは**キーを離しても保持**する
- ミス条件は3つ: 敵に触れる／**体温がオーバーヒート**／落下してきた岩に潰される
- ミス後 90フレーム（1.5秒）無敵

### 体温と水風呂

- 15フレームごとに体温+1、上限240 = **60秒でオーバーヒート**して1ミス
- **つるはしを1回振るごとに体温+4**（`HEAT_PER_SWING`）。掘る量そのものが体温に効く
- 盤面に**水風呂が1つ**。**1pxでも重なっていれば**1フレームに `BATH_COOL`(2) ずつ下がる。
  **何度でも入れる**（史実の反復入浴。`HISTORY.md` §2.1）
- 冷えている間は**湯の中を泡が上がる**（効いていることを画面で見せるため）
- 水風呂は**落下してきた岩で壊れる**（壊れるとその面では復活しない）。ダイナマイトでは壊れない

### 制限時間 ── 1面3分（2026-09-26）

**敵は掘り方と岩でいくらでも牽制できる。** 詰まったら安全な隅で待つのが常に正解になり、
**時間さえかければどの面も抜けられてしまう**（作者の指摘）。時間の側から押し返すために、
面ごとの持ち時間を置いた。

| | |
|---|---|
| 持ち時間 | **面ごとに決める**（`tlimit_tbl[]`、`src/tlimit.c`。10秒単位の表）。**いまは全面180秒**。HUD の下段の右端に砂時計と「分:秒」で出る |
| 残り30秒 | **急かすファンファーレ**（`TLIMIT_WARN`。曲を止めて約0.8秒鳴らし、そのあと坑内の曲へ戻る）。以後、**数字が赤くなり砂時計が1秒ごとに点滅する** |
| 0秒 | **時間切れで1ミス。** 画面の中央に大きく **TIME OVER**（オーバーヒートの `HEATSTROKE` と同じ出し方） |
| ミスのあと | **持ち時間は満タンに戻る。** 0秒のまま復帰すると、出た瞬間にまた時間切れになって残機を全部持っていかれる |

**死因は増えるが、形は体温と同じ**「時間切れ」にしてある。体温が「掘りすぎ」の時計、
持ち時間が「面そのもの」の時計で、どちらも**待っていると負ける**方向に働く。

**持ち時間は面ごとの表で持つ**（作者の指示、2026-09-26）。**後半面は盤面が大きく
黒ダイヤも多い**ので、3分で足りるかは遊んでみないと分からない。
`src/tlimit.c` の `tlimit_tbl[]` を書き換えるだけで面ごとに変えられる
（1面1バイト = 10秒単位。18 = 180秒）。

### クリアしたら残り時間を得点へ換える

**クリアのファンファーレが鳴り終わってから、残り時間が高速に減って、そのぶん
スコアが上がる**（悪魔城ドラキュラのボーナス集計と同じ見せ方。作者の案）。

| | |
|---|---|
| 速さ | 1周につき **4秒ぶん**（`TL_DRAIN`）。3分満タンでも**約2.4秒**で換え終わる（実測） |
| 点 | **残り1秒あたり10点**（`PTS_TIME`）。3分満タンで1800点 |
| 音 | 短く高い刻み音（`SFX_TALLY`）を2周に1回。1秒に8回ほど「チチチチ」と鳴る |
| 表示 | 数字だけを描き直す（砂時計は触らない）。換え終わるまで次の面へ行かない |

**速く抜けるほど点が高い**ので、制限時間が「急かすだけのもの」で終わらない。

**【不具合・修正済み】刻み音が一度も鳴らなかった**（2026-09-26）: 鳴らす間隔を
**残り秒数**で数えていた（`tl_left & 7`）。1周に2秒ずつ減らしていたので、
**残りが奇数の面では条件に一度も当たらなかった**。録音して波形を見て気付いた。
いまはフレームで数えている。

**描くのは変わった桁だけ。** 毎秒まるごと描き直すと、それだけで 59.6fps が 57.5 まで
落ちた（openMSX で実測）。普段は一の位の1文字、十の位は10秒に一度、「分:」は1分に一度。
いまの落ち込みは約1fps（面1: 59.6 -> 58.5、面7: 56.1 -> 55.3）。

### 梅干し

- **岩で潰した敵が必ず落とす**。拾うと体温 **-60**（`UME_COOL`、メーターの1/4）
- ダイナマイトで倒した敵は代わりに**火薬を半々で**落とす
- 岩は資源を使わないぶん、時間を買える梅干しで報われる構図

## 4. 黒ダイヤ（石炭）＝ クリア条件

**盤面の黒ダイヤを全部採掘したらステージクリア。炭柱も数に入る（＝必ず壊す）。**

- 土と違い**掘り進めない障害物**。自機も敵も通れない
- **耐久度**を持ち、つるはしで1回叩くごとに1減る。残りは升の**右上に数字で表示**
- 耐久度0で**割れた絵に変わり、通れる升になる**。同時に**土の膜も開く**（`link_open`）ので、
  炭層を全部割ると最大4升の直線通路が開通し、**敵の高速道路になる**
- **割れたまま放置すると、敵が踏み抜けた升は耐久1で塞がり直す**（`REFILL_HP`）。
  割った升は通れて土の膜も開くので、**仕込んだ連鎖はそのまま敵の通り道**になる。
  3個目を割っている間に1個目を踏まれたら仕込みが崩れる。Dig Dug で
  「1列に集めた敵が散ってしまう」に相当する部分で、**代償を面番号ではなく
  野心の大きさに連動させる**ための中心。
  - **1個ずつ割って即座に採る人には一度も発動しない**（放置時間が0だから）
  - **詰まない。** 耐久1で戻るだけなので1振りで割り直せる。`coal_left` も変わらない
  - 同じ升は `REFILL_COOLDOWN` 300フレーム（5秒）続けて塞がらない
  - **炭柱は対象外**（耐久が高く割り直しの代償が大きすぎる）。透明化中の敵も対象外
  - **敵や自機が居座っている升は塞がない**（土に埋めて動けなくしないため）
  - `dug_n` は減らさない。切羽圧は増分で測っているので、減らすと
    「埋め戻されるほど安全になる」という逆向きの力が働く
- 割れた瞬間: 破砕音＋画面を縦に揺らす（R#18 = SET ADJUST）
- 配置は1個ずつではなく**繋がった炭層**（1本あたり最大4個 `COAL_VEIN_MAX`）

### 連鎖採掘

**割れた黒ダイヤの升に入ると、繋がっている割れた黒ダイヤをすべて同時に採る。**
さらに **連鎖は時間で繋がる**（`CHAIN_WINDOW` 180フレーム＝3秒）。

- **岩が突き抜けて採った黒ダイヤも、自分で歩いて採った黒ダイヤも、同じ連鎖として数える**
- 得点は**採った順**に 200 → 400 → 800 → … と倍々（1個あたり `CHAIN_PTS_MAX` 3200 で頭打ち）。
  岩は上から下へ抜けるので、その順に倍率が上がっていく
- 一度に採れるのは `CHAIN_MAX` 8個まで
- 効果音の音程が1個ごとに3半音上がり、画面の揺れも個数に応じて大きくなる
- 連鎖が伸びた瞬間だけ**ヒットストップ**（2〜7フレーム全部止まる。§13）
- HUD に連鎖数（×2 以上）を1.5秒表示

**これが本作の爽快感の核。** 岩を落として鉱脈を貫かせ、その連鎖が切れないうちに
自分でも採りに走る、という組み立てになる。

**溜めるには回り道を掘る必要がある。** 縦の炭層で1個目を割った後、2個目に隣接するには、
割れた1個目の升を通る（＝入った瞬間に回収されてしまう）か、横に別の穴を掘るかしかない。
つまり「全部割ってから一気に採る」は**追加の掘削コストを払う選択**であり、掘れば体温も
切羽圧（§7）も上がる。**狙いどおりのギャンブルにはなっているが、プレイヤーがこの形に
気づくかは別問題。**

### 炭柱（残柱式）

**耐久が高く、絵が違い、壊すと黒ダイヤに載っている岩が一斉に落ちる黒ダイヤ。** 面に最大2本。

- 絵は専用のもの（史実の**三ツ枠**＝冠木＋両柱を巻いた姿）
- 耐久は通常の黒ダイヤ +3（上限8）
- 升の**右上に残り耐久度**を出す
- 岩とは**無関係な場所**に置く。落盤で全部の岩が落ちるので、真上の岩だけ特別扱いする
  理由が無く、「黄枠 = 天井全部が落ちる」という合図のほうが挙動と一致する
- 必ず壊すので、**本数がそのまま強制的な発熱**になる（面1で1本20、面15で32）

### つるはし（溜め打ち）

- **向きさえ決まっていれば必ず振る。** 当たるものが無くても空振りする
- 1回振り切るまで **18フレーム（0.3秒）動けない**。ここに敵が寄ってくるのが駆け引き
- **使用回数は無制限**

```
押した瞬間  →  威力1で即座に1振り（単発の手触りは変わらない）
押したまま  →  **振らずに気合いを溜める**。0.5秒ごとに1段、最大3段
離した      →  溜まっていれば、その威力で1振り
移動した    →  溜めが切れる
```

- 威力ぶん黒ダイヤを削り、敵はその段数ぶん深くよろける
- **発熱は威力に比例する**（威力3で+12）。空振りでも発熱する。
  比例させないと「掘りは常に押しっぱなし」が最適になり、体温が骨抜きになる。
  溜めが買っているのは**時間**であって熱ではない
- 効果音は当たれば金属音（溜めるほど高い）、空振りは低い「コツン」
- 溜め中は**腰を落とした構え**になり、**つるはしを振り上げ**、**汗が飛ぶ**
  （つるはしと汗はスプライトではなく背景に描いている。§13）

## 5. ダイナマイト（投げる武器）

- **弾薬制。面の開始時のストックは0**。火薬を拾うと+1、**次の面へ持ち越す**
- B ボタンで**向いている方向へ投げる**。最大**5升**飛ぶ（1升4フレーム）
- 飛行中に**敵が居ればそこで爆発**。**爆風は1升だけ**で、
  **地形は掘らない／土の膜も壊さない／水風呂も壊さない／岩も壊さない**
- 敵以外の障害物があれば**その手前に落ちる**。何にも当たらなければ5升先に落ちる
- 落ちたダイナマイトは**アイテム**。拾い直せる。障害物にならず、敵は素通りする
- **投げる先が塞がっていると投げない**（消費もしない）。ただし隣に敵が居れば投げられる
- 同時に飛ばせるのは1個
- 火薬は面ごとに**10個**（面によらず一定）

## 6. 岩

> **ここは「何が起きるか」の章。** 見せ方（音・揺れ・光）は §13 にまとめてある。

**岩の規則は6つ。それで全部。**

```
1. 真下が塞がっていれば止まる（支えは岩の中心で見る）
2. 左右に押せる
3. 落ちる先が黒ダイヤなら、貫いて採る
4. 落ちる先が樋（とい）なら、板を壊して、傾いている方向へ1升ずれてから落ち続ける
5. 2升以上落ちるか、何かを潰したら割れる
6. 落ちてきた岩が岩に着地したら、落ちてきたほうが割れる
   （押して岩の上に乗せた場合は割れない ＝ 積める）
```

- 面ごとに **4〜8個**（`4 + (面-1)/3`、上限8）
- **1行に1個まで。** スプライトは16px高なので別の升行なら走査線が重ならず、
  MSX2 の「横一列に9枚目以降が消える」制限を確定的に避けられる。
  岩は自力で行を移動しない（樋で横へ1升ずれても行は変わらない）ので、
  **初期配置で守れば最後まで守られる**

---

### 6.1 止まっているとき（規則1）

| 真下 | |
|---|---|
| 土 / 割れていない黒ダイヤ / 別の岩 / 盤面の底 | **支えられる。動かない** |
| **自機** | **支えられる**（真下に立っている間は落ちてこない。Dig Dug 準拠。好きなだけ待てる） |
| 坑道 | 支えが無い → `ROCK_JIG_FRAMES` 45フレーム揺れてから落ちる |

**割れていない黒ダイヤは坑道ではない**ので、岩の支えになる。割ると坑道になる。

> **割る＝通す。割らない＝支える。**
> 連鎖を組むとは、どの升を通し、どの升で支えるかを決める作業のこと。

---

### 6.2 押す（規則2。Mr. Do! 準拠）

- **左右のみ。上下には押せない**
- **ドット単位。** 押し手が1ドット進むたびに岩も1ドット動くので、
  升ごとに瞬間移動せず**押し手と同じ速さで並んで動く**
- **自機は土の中へも押し込める。** 押し込んだ先は土のまま残り、岩が退いた升は
  自機が入って掘る。これで**岩の X 座標を好きな位置へ運べる**
- **敵は坑道の中でしか動かせない。** 敵にも土への押し出しを許すと、敵が岩を勝手に
  運んでしまい「自分で落下位置を決める」遊びが壊れる。**意図的な非対称**
- **横押しでは何も潰れない。** 敵は1升後ろへ下がる。下がれない敵は壁になって岩が止まる。
  **潰せるのは落ちてきた岩だけ**
- 黒ダイヤ・炭柱・別の岩・水風呂・場外へは押せない
- **支えの判定は岩の中心**（半分を越えたら次の升の住人）。だから
  **縁からせり出しても、越えるまでは落ちない**。**ぶつかりの判定は進む側の端**
- 中心が升の境目を越えた瞬間に「カチッ」と鳴る（`SFX_CLICK`）。落ちる場合も落ちない場合も鳴る
- **押して岩の上に岩を乗せられる**（規則6の「置いただけなら壊れない」）。
  下の岩の支えを外せば、下が先に落ちて炭層を貫き、遅れて上が同じ穴へ落ちる。
  **時間差の縦連鎖を、プレイヤーが自分で仕込める**

### 6.3 落ちている間（規則3）

- **2px/フレーム**（1升8フレーム）
- **列の黒ダイヤを、割れていようがいまいが全部貫いてその場で採る**（`coal_smash`）。
  採ったぶんは連鎖に乗るので、倍率が上から下へ伸びていく。
  **これが連鎖の心臓。** 岩の真下を1枚割るだけの手間で、炭層の帯を丸ごと持っていける
- **縦一列の敵をまとめて潰す。** 1回の落下ぶんをまとめて計上する
- 通り抜けた升の**縦の土の膜を突き破る**（`link_smash`）
- **落ちてきた岩は水風呂を壊さない**

**支えとして黒ダイヤを数えるのは静止している岩だけ**（規則1）。落下中は貫く。
この非対称が「割る＝通す／割らない＝支える」を成立させている。

**貫いても、続けるかどうかは真下の支えを見て決める。** 炭層の下が土なら、
貫き終わった升で止まる（土の中へめり込まない）。落ち続けられるのは
**真下が坑道か黒ダイヤ**のときだけ。

### 6.4 樋（とい）— 横へ動く唯一の手段（規則4）

**炭鉱のシュート。石炭を上の坑道から下へ落とすために斜めに架けた木の板。**
坑木や板を斜めに組んで作り、掘った石炭を人力で運ばずに重力で下ろした。
常磐炭田は炭層が海側へ7〜10度傾斜していたので、この手の落とし込みは日常的だった。

```
     ＼            ／
      ＼          ／
   左下がりの板   右下がりの板
   → 岩は左へ    → 岩は右へ
```

| | |
|---|---|
| 枚数 | **低次面2枚 / 面8以降4枚**（`CHUTE_LOW` / `CHUTE_HIGH`） |
| 置き場所 | **板の升と、板が落とす先の升が、面の最初から開いている。**土に埋まっていない |
| つるはし | **壊せない。** 壊すのは落ちてきた岩だけ |
| 落ちてきた岩が通ると | **板は必ず壊れる。**壊れた升は通れる坑道になり、**「折れた板」の絵が跡として残る**（向きも残る） |
| 曲がれる先 | 落とす先は開けてあるので**必ず曲がる。** 例外は、そこに後から岩が入った場合と場外 |
| 曲がった先に敵 | 潰す（落下中なので既存の撃破処理がそのまま効く） |
| 曲がった先に岩 | **曲がらない**（塞ぐものに岩を含める）。板は壊れ、そのまま真下へ落ちる。横から押しても岩は岩を通り抜けられないので、押しの挙動と一致する |
| 曲がった1升 | **落下距離に数えない**（数えると樋を通った岩がすぐ砕けて連鎖が続かない） |
| 押している岩が通っても | **何も起きない。** 板を壊すのは落下の衝撃、という一貫性 |

**絵そのものが規則になっている。** 板が右を向いていれば岩は右へ行く。
落とす先まで開けてあるので、**落とす前に、盤面を見るだけで岩の通り道を最後まで
指でなぞれる。** ぷよぷよで連鎖を組む前に目で追えるのと同じ状態にするための機構。

**消耗品なので順番が意味を持つ。** 面に2〜4枚しかない使い切りの資源だから、
「どの岩をどの板に通すか」が計画になる。

#### 【記録】「掘り出すまで岩は通れない」は廃止した（2026-09-12）

提案書の細部①は **「板は土の升の中に、最初から見えている。掘り出すまで岩は通れない」**
で、「岩から板まで穴を掘る」を仕込みの作業にする狙いだった。**動かしてみたら破綻していた。**

面1の実例（種50399）。盤面はこう並んでいた。

```
(0,0) 岩
(0,1) 黒ダイヤ耐久2       ← 4枚の縦の炭層
(0,2) 〃
(0,3) 〃
(0,4) 〃
(0,5) 樋（右下がり）
(1,6) 炭柱
```

**盤面は「岩→炭層4枚→樋→炭柱」という連鎖を絵で約束している。** ところが、

1. **樋の升が土なので、岩は (0,4) で止まる。**
   硬い黒ダイヤを4枚貫いた岩が、柔らかい土に止められる。**規則として通らない**
2. 仮に入れても、曲がった先 (1,5) も土なので**曲がれない。**
   板は一度も働かない

**樋は土の塊ではなく落とし口**なので、板の升とその落とし先を最初から開けた。
結果、面1は絵の通りに動く。

```
つるはしで (0,1) を2振り割るだけ
  53f 採掘 連鎖1   ← 岩が炭層を上から貫く
  61f 採掘 連鎖2
  69f 採掘 連鎖3
  77f 採掘 連鎖4
  93f 樋で 1 列へ  ← 板を壊して右へずれる
 101f 採掘 連鎖5   ← 曲がった先の炭柱を貫く
  => この1手で5個（面の黒ダイヤ6個のうち5個）
```

仕込みの作業は「板まで掘る」ではなく、**「どの岩をどの板へ通すか」を選び、
必要なら押して運ぶ**ほうに寄せた。

### 6.5 落盤（炭柱を壊す）

**炭柱を割ると、黒ダイヤに載っている岩が一斉に支えを失って落ちる。**

- **炭柱が無くなれば、誰が壊しても落盤になる**（2026-09-27）。つるはしで割り切った
  ときだけでなく、**落ちてきた岩が炭柱を貫いて消したとき**も落ちる。
  以前は後者が落盤にならず、**同じ「炭柱が無くなった」でも結果が違っていた**
  （作者の指摘「今のルールはわかりづらい」）。面7では出水の引き金もこれなので、
  「炭柱が消えたのに水が出ない」ことがあった。
  **岩を1つずつ見ている最中には起こさない。** 予約しておいて、
  `rock_update()` が全部見終わってから落とす（`rock_collapse_later`）
- 岩の真下が**黒ダイヤ**ならそれが割れる（`coal_crack_by_rock`）。支えが消えるので普通に落ちる
- 岩の真下が**土・坑道・盤面の底**なら**何も起きない。** その岩はその場に残る
- **落ちる岩は全部同じフレームに落ち始める**（`ROCK_JIG_FRAMES` 45フレーム揺れてから）
- 専用の効果音・全画面の閃光・**全敵を1段よろけさせる**が同時に起きる

#### 同時に落とす理由 ── 隠れた時間の貸し借りを消す（2026-09-12）

以前は上の行の岩から順に落としていた（`45 + 行番号 × 10` フレーム）。
**上を先行させると下の岩に追いつく。追突を防ぐどころか作っていた。**

実際に面1で、先に落ち始めた岩が樋で横に8フレーム迂回したせいで、
あとから落ち始めた岩に**4フレーム差**で板を取られた。
**その4フレームは盤面のどこにも書かれていない。**

```
1升落ちる      8フレーム
樋を横に渡る    8フレーム
行ごとのずれ   10フレーム   ← これだけが升で割り切れない
```

**新しい量を作って画面に出すのではなく、単位を揃えて量そのものを消した。**

> **岩は常に 2px/フレームで動く。下へか、樋では横へ。**

速さは一定で向きだけが変わる。樋は1段ぶんの時間を食うが、高さは変わらない。
結果、**勝敗は経路の升数だけで決まる**ようになった。

```
岩A(9,1)  (9,2)→(9,3)→(9,4)→樋(9,5)→横→(8,6)→(8,7)   7升
岩B(8,3)  (8,4)→(8,5)→(8,6)→(8,7)                      4升
                                    岩B が3升ぶん先に着く
```

**指でなぞって数えられる。** そして**どの岩も同じ速さで動くので、前の岩が止まらない限り
後ろの岩が追いつくことが構造的に起きない**（落下中の岩どうしに限った話で、
プレイヤーが途中で別の岩の下を掘った場合などは除く）。

全15面の実測（変更前→変更後、種は同じ）: 岩どうしの追突 0→0、
横から入られた 0→0、樋を通った回数 38→38、つるはし1本で採れた数 54→54、
**落盤の所要フレーム 2827→2345（−17%）**、**走査線に重なる岩の最大 4→3**。
**結果は変わらず、短くなり、スプライトの負荷は下がった。**

**岩は土を突き抜けない。** ここは2回間違えて2回とも捨てた。

| 試した案 | 捨てた理由 |
|---|---|
| **沈み込み**（炭柱に書かれた数だけ沈み、その間は何でも素通り） | 数字が別の物の升にあり、どこまで沈むか見えない |
| **土もろとも落ちる**（真下の土を抜きながら底まで落ち、跡が縦の坑道として残る） | **掘っていない場所を岩が落ちていくのが、爽快感より違和感になる**（作者の指摘、2026-09-11）。結果が盤面に残る点は改善だったが、絵として通らない |

**岩は `keep_above_coal()` で黒ダイヤの真上へ寄せて置いてある**ので、低次面では
ほとんどの岩が落盤で落ちる。落ちた岩は炭層の帯を貫いて採るので、炭柱ひとつが
**「盤面のあちこちで縦の連鎖が同時に走る」合図**になる。

土の中に取り残された岩は、押して運ぶか、真下を掘って落とすしかない。
**落盤で全部が片付くわけではない**ので、押して運ぶ遊びが面の後半まで残る。

#### ずらして置く岩 ── 面が進むと自分で揃える（2026-09-16）

**面2から、岩の一部を炭層の真上から横へずらして置く。** 押して黒ダイヤの真上へ
揃えないと、割っても落盤でも炭層を貫かない。

| 面 | 1 | 2〜3 | 4〜6 | 7〜9 | 10〜12 | 13〜15 |
|---|---|---|---|---|---|---|
| 岩 | 4 | 4 | 5 | 6 | 7 | 8 |
| **ずらす岩** | 0 | 1 | 2 | 2 | 3 | 3 |
| 押す距離 | ― | 1列 | 1列 | 1列 | 1〜2列 | 1〜2列 |

（2026-09-19 に増やした。以前は面4から1個ずつで、「1個押せば済む」盤面が多かった。
作者の指摘「岩を動かして準備してからの爽快感であるカタルシスは得られない」）

ずらす岩は**必ず押して揃えられる形**にだけ置く（`src/field.c` の `off_path_ok()`）。

```
  押し手   岩   通り道   行き先
  [  ]    [O]   [  ]    [  ]     ← この行
          [土]  [土]    [炭]     ← 真下
```

- 通り道の真下は**土**（坑道だと押している途中で落ちる。黒ダイヤだとそこで揃ってしまう）
- 行き先の真下が**黒ダイヤ**
- 押し手が立つ升・通り道・通り道の真下は**予約**して、後から置く炭柱や樋で塞がない
- 水風呂と湧き出し口の升は通り道にしない

**揃えたあとの一手は2つある。** 真下の黒ダイヤを割る（その列だけ落ちる）か、
炭柱を割る（揃えた岩も落盤に加わる）。落盤の判定は炭柱を割った瞬間の位置で行うので、
**運んでおいた岩もほかの岩と同じフレームに落ちる。**

**ずらす岩を先に置く。** 置ける形が限られるので、真上の岩に炭層の上の升と行を
先に取られると、ほとんど置けなくなる（実測で候補0が95%）。

#### 左右に散らす（2026-09-19）

**炭層・炭柱・岩は、左半分と右半分へ交互に置く**（`take_candidate_side()`）。
その側に置ける升が無いときだけ、反対側も許す。

以前は何も指定しておらず、**右側だけ・左側だけに固まる盤面が多かった**（作者の指摘）。
出荷していた15面で、少ない側の黒ダイヤは平均24%。面1・3・4・10 は左半分に1つも無かった。
原因は2つあった。

1. 置き方そのものが偏りやすい（無作為の盤面でも少ない側は平均30%）
2. **種選びが偏りを強めていた。** 岩と炭層が固まっているほど少ない手で連鎖が伸びるので、
   「押さない一手で何個採れるか」を狙いに合わせると、固まった盤面が選ばれやすい

交互に置くと無作為でも39%になり、さらに種選びで「少ない側が黒ダイヤ・岩とも3割以上」を
必須にした。出荷中の15面は黒ダイヤ41%・岩46%（どちらも50%で均等）。

**面の組み立ては少し重くなった。** 同じ種で比べた暗転（openMSX、Z80）は
面13で 3.28 → 3.58秒、面15で 3.11 → 3.36秒。最初は +0.43秒あったのを、
候補の一覧を作り直さずに控えて使い回し、行に岩が居ない前提で岩の走査を省いて縮めた。

### 6.6 割れて消える条件（規則5・6）

**2升以上落ちた**か、**何かを潰した**か、**落ちて別の岩に着地した**とき。

- 即消しではなく、**二つに割れた姿を `ROCK_SPLIT_FRAMES` 60フレーム見せてから**消す
  （即座に消すと何が起きたか読み取れない）
- 割れると軽く画面が揺れる
- **岩を2個割ると盤面中央にボーナスが出る**（10秒で消える）
- **押して岩の上に乗せた場合は割れない。** 判定は落下中にしか走らない。
  **ぶつかったら壊れる、置いただけなら壊れない**——説明の要らない区別にしてある

### 6.7 【記録】ここから消した4つの機構（2026-09-10）

| 消したもの | 何だったか | 消した理由 |
|---|---|---|
| **沈み込み** | 落盤で岩が「炭柱に書かれた数」だけ沈み、その間は何でも素通りした | ゲーム内に類例が無く、数字が別の物の升に書いてあり、どこまで沈むか見えなかった。**「行差＝沈み込み＋1」という不可視の条件**を生み、横滑りをほぼ不可能にしていた |
| **土もろとも落ちる** | 落盤の岩が真下の土を抜きながら底まで落ち、跡が縦の坑道として残る（沈み込みの代替として一度入れた） | **掘っていない場所を岩が落ちていくのが違和感になる。** 沈み込みと同じ「岩が土を通る」を、掘りながらやっているだけだった |
| **横滑り** | 岩が岩に乗ると、下の岩が「坑道がちょうど一方だけ」の側へ1升滑る | 条件が狭すぎて15面で1回しか起きなかった。**出会えないのに覚えなければいけない規則** |
| **着地衝撃波** | 止まった升から左右3升へ、距離で減衰する衝撃を送って黒ダイヤを削った | 三角形の減衰は**盤面上で暗算しないと結果が読めない** |
| **倒れ込み** | 衝撃で真横の黒ダイヤが割れたら、岩がその穴へ倒れ込んだ | 衝撃波とセットの機構だったので同時に取り下げ |

**診断は「ギミックの数」ではなく「1つの物に付いた規則の数」だった。**
岩1つを理解するのに8つ覚える必要があり、しかもそのうち3つは**同じ絵（岩）で起きる**
ので区別がつかなかった。横方向の移動を**樋という別の絵**へ全部移した結果、
岩の規則は6つになり、横へ動く条件は**盤面を見れば分かる**ようになった。

相談と結論の全文は `docs/ROCK_RULES_TOI.md`（旧機構の実測は `docs/ROCK_SLIDE.md`）。

## 7. 敵

姿は4種とも同じで**色だけが違う**。**色ごとに狙う升の決め方が違う**（パックマンのゴースト準拠）。

| 色 | 役 | 狙う升 | 速さ |
|---|---|---|---|
| 赤 | 追いかけ | 自機の升そのもの | 35px/s |
| 桃 | 待ち伏せ | 自機が向いている方向の**4升先** | 30px/s |
| 水 | 気まぐれ | 自機の2升先を、**赤の位置から見て倍に伸ばした升**（＝敵同士の連携） | 30px/s |
| 橙 | お惚け | 自機まで6升より遠ければ追い、**近いと自分の隅へ引く** | 25px/s |

- 全員が**「散開」5秒 ⇄「追跡」20秒**を切り替える
- 交差点では**引き返し以外で狙う升にいちばん近づく方向**を選ぶ（同点は 上→左→下→右）。
  ただし 1/16 の確率だけランダムに揺らす
- **敵は自分で掘らない**（Dig Dug 準拠）。自機が掘った坑道しか歩けない
- **土の膜が残っている境目は歩いて抜けられない**（§8）

### よろけ（つるはしで潰す）
- **透明化している敵にも当たる（Dig Dug 準拠）。** つるはしは土ごと叩くもの、と
  考えれば筋も通る。**よろけている間は透明でも実体の色で描く**ので、叩いた手応えが
  画面に出る。ダイナマイトは坑道の中しか飛ばないので、そちらは当たらないまま

**つるはしで叩くと潰れて動けなくなり、触れてもミスにならない。**

- 深さは3段。叩くほど深くなり、**時間で1段ずつ戻る**（1段2秒）。
  戻っていく姿がそのまま「あと何秒で復活するか」の表示になる
- 見た目は**潰れていく**（縦11行 → 9 → 7 → 4）。ディグダグの「膨らむ」の逆にして、
  真似に見えないようにしてある。**色は変えない**（色は敵のアルゴリズムを表す情報）
- 潰れている敵は**動かない**ので、岩の下へ並べてまとめて潰す狙いが成立する
- 向いている方向へ**2升**探して、**一番手前の敵1体だけ**に効く。
  ただし既に最深の敵は飛ばして後ろを狙うので、「先頭を潰す → 通り抜ける → 次を潰す」
  が組み立てられる
- 透明化中の敵は叩けない（ダイナマイトと揃えてある）

### 透明化と切羽圧

- 一定時間経つと**透明化して土を斜めにすり抜ける**。この間の速さは **7.5px/s**（素の1/5程度）
- 透明中も**触れると死ぬ**
- **透明化までの時間は、面番号だけでなく「自分が掘った升の数」でも縮む**（切羽圧）。
  1升掘るごとに `GHOST_PRESSURE`(3) フレーム短くなる。
  面1の例: 開始16升で10.0秒 → 60升で7.8秒 → 120升で5.0秒（下限5秒）
- **掘るほど危険が増すが、掘らないとクリアできない**という本作の芯をここで成立させている

### 湧き出し口とプール制

- 面番号の掘り抜きとは別に、**坑道に面した升に1ブロックの横穴**を開ける。出発点から6升以上離す
- 湧いた敵は**2秒間その場で点滅**する。その間は動かず、触れても当たらない

**敵はプール制**（パックマン方式）。「合計N体を出し切ったら打ち止め」ではない。

- 面ごとにプール数が決まっている（面1で3体 → 面10以降は6体）
- 面の頭は全員が洞窟に居て、**1.5秒間隔で1体ずつ**出てくる
- **倒された敵は消えない。洞窟で静養してから同じ個体が戻ってくる**（面1で10秒、面15で4秒）
- つまり**新規の出現間隔（短い）と、倒された後の復帰間隔（長い）が別**

## 7b. 出水（熱水）── 第三坑のギミック（2026-09-21、面7で試験導入）

**炭柱を割って落盤が起きると、盤面の湧き出し口から熱水が湧き、坑道を伝って広がる。**

史実では常磐は石炭1トンに40トンの湯が湧き、当時世界最大級の排水ポンプを並べていた。
坑内水は温泉なので熱い（`docs/HISTORY.md` §2）。

| | |
|---|---|
| どこから | **湧き出し口**。面の開始から盤面に見えている（掘り抜きの上の1升。出発点から4升以上離す） |
| いつ | **落盤の1秒後**（天盤が落ち、1拍置いて湧き出し口から噴き出す）。**落盤の起こし方は問わない**（つるはしで割っても、落ちてきた岩が炭柱を貫いても。§6.5） |
| 速さ | **1秒に1回**（`WATER_STEP` 60フレーム）。**1回で、その向きへ行ける升を全部いっぺんに満たす**ので、分かれ道では両方へ同時に流れる |
| 音 | 噴き出した瞬間に**「ゴボッ」**（`SFX_GUSH`）、1升広がるたびに小さく**「ポチャ」**（`SFX_DRIP`、優先度が一番低いのでほかの音を止めない） |
| 向き | **下を優先**、次に横、最後に上。優先は盤面全体でひとつ（下へ行ける升がどこかにあれば、その回は下だけ） |
| 通る升 | **湧き出し口からつながった坑道だけ。** 土・黒ダイヤ・**落ちた岩**は通らない。**土の膜で仕切られた隣の坑道へは行かない**（敵と同じ `cell_linked` で判定） |
| 通らない升 | **水風呂**（冷やす手段を奪うと立て直せない）と**敵の巣**（塞ぐと敵が一体も出て来られない） |
| 拾い物 | **火薬・落ちたダイナマイト・梅干しは水に浮く。** 水は止まらず流れ込むが、**絵は水の上へ描き直す**ので見えたまま拾える（2026-09-28） |
| **止まる** | **次の増水で24升（`WATER_MAX`）を超えるとき**は、その増水をやらずに止める。または**広がれる升が無い状態が3秒続いた**とき（`WATER_STALL`）。**止まったら二度と増えない**（その後に掘っても流れ込まない）。分かれ道で同時に流れるので、ちょうど24升にはならない |
| **止まった印** | **水の縁のうち「坑道が続いているのに水が来ない面」すべてに、岩の色の帯（3px）を引く**。上下左右どの向きでも「ここで止まった」と分かる。あわせて**湧き出し口の絵が「割れ目が塞がった絵」に変わり、「シュウ…」と鳴る**（`SFX_SEAL`）。湧き出し口は水に沈めず、いつも見えている |
| 浸かると | **体温が毎フレーム +1**（`WATER_HEAT`）。0から約4秒でオーバーヒート |
| 敵 | **熱水には入らない。** 熱いが安全な升になる |
| 採掘 | **妨げない。** 水の升でも黒ダイヤは叩けるし採れる |

**拾い物は沈めず浮かせる**（2026-09-28）: 水が拾い物の升を覆うと絵が隠れ、
**見えないのに踏めば拾える物**がそこにある状態になっていた（作者の指摘）。
**最初は「水のほうが拾い物を避ける」ことにして測った**（水風呂・敵の巣と同じ扱い）が、
**火薬は1面に10個撒いてある**ので拾い物が水を止めるものになり、面7の熱水が
**13升 → 2升**しか広がらなくなった（`hostsim --water` で実測）。出水が起きていないのと
同じなので取りやめ、**水は流すが絵を水の上へ描き直す**ことにした。

**分岐は同時に流れる／止まった印を全方位に**（2026-09-23）: 作者の指摘
「上に上がって左右分岐あるのに最初左に行くのが意味不明」「止まりは全方向で分からないと
意味がない」。1升ずつ順に流していたのをやめ、**その回に行ける升を全部いっぺんに**満たす
ようにした。上限は「ちょうど24升」ではなく**「次の増水で24を超えるならやらずに止める」**。
止まった印は湧き出し口だけでなく、**水の縁の開いている面すべて**に岩の色の帯を引く。

**止まった印**（2026-09-22）: 以前は止まっても何の印も無く、24升に達して止まったのか、
行き先が無くて待っているだけ（掘ればまた流れ込む）なのかが分からなかった（作者の指摘
「これ以上浸水しないか、するかがわからない。明確な印がほしい」）。**止まる条件を
「上限に達した／3秒広がれなかった」にまとめて止まったら二度と増えないようにし、**
湧き出し口の絵と音で示すようにした。最初の1升が湧き出し口そのものなので、以前は水が出た
瞬間に湧き出し口の絵が水に隠れていた。いまは湧き出し口の升だけ水を描かずに湧き出し口を描く
（体温の判定は水のまま）。openMSX で、13升まで広がって3秒後に止まり、湧き出し口の絵が
噴く絵（赤20画素）から塞がった絵（赤0・灰9画素）に変わって音が鳴ることを確認した。

**合図の音と1拍の間**（2026-09-22）: 最初は落盤と同時に水を出していて、落盤の「ゴゴゴ」と
閃光に紛れて**離れた場所で静かに始まっていた**（作者の指摘「よくわからなかった」）。
いまは**落盤 → 1秒後に「ゴボッ」と噴き出す → 1升ごとに「ポチャ」**の順。原因（天盤が落ちた）
と結果（湯が噴いた）が耳でも分かれる。openMSX で PSG を毎フレーム読み、落盤の約1.2秒後に
噴き出しの音、以後1升ごとに滴の音が鳴ることを確認した。

**【不具合・修正済み】見えない熱水**（2026-09-22）: 自機は動くたびに自分の周り12×12を
坑道の黒で塗り直す（`player_carve`）。そのあと重なった升の絵を描き直すが、**熱水だけが
抜けていた**ので、自機が通った升の水の絵が消え、**見た目は空の坑道なのに体温が上がり続けた**
（作者の指摘「何もないところに行っても体温上昇が早い。実質詰み」）。openMSX で、直す前は
水の中を歩くと4升の絵が消え、直した後は0升になることを確認した。

**見た目**（2026-09-22 に描き直した）: **坑道の形どおりに青い湯を塗る。**
つながった水の升どうしは縁の2pxまで塗り合って隙間なく1つの形になり、上に水が無い升は
水位（升の上から7px）より上に坑道の黒を残して、**水面に赤い線と湯気**を描く。
タイルは使わず塗りつぶしだけ。湧き出し口は、岩肌の割れ目から赤い湯が噴き出して青い湯に溜まる絵。

**「つながった坑道を満たしていくもの」として描き直した**（作者の指摘「近隣の掘った箇所を
沸騰水で満たしていくということなら、全部つながっていないと変」）。以前は升ごとのタイルで、
升と升の間に黒い隙間が残って**ブロックが1個ずつ現れる**ように見え、しかも**土の膜を無視して
壁の向こうの坑道へしみ出していた**ので、増え方が理不尽に見えていた。

**【不具合・修正済み】湧き出し口が拾われたように消える**（2026-09-22）: 自機が上を通ると、
描き直す対象に湧き出し口が入っていなかったので絵が消えた。「見えない熱水」と同じ原因。

最初は**橙の塊を升いっぱいに**描いていて、作者に「**粘土っぽいブロック**」と言われた。
坑道が塞がったように見え、通れる水だと分からなかった。橙のまま筋を入れる案（A）、
青くする案（B）、青くして水面だけ赤く熱する案（C）を実際の画面で見比べ、C に決めた。
**水風呂（冷やす湯）と色が近い**ので、水面の赤で「熱い湯」だと区別している。

**新しい死因を作らない。** 失敗条件は既存のオーバーヒートのままで、
**「なぜ水風呂が要るのか」の説明**になる。そして**自分が掘った坑道を通ってくる**ので、
「掘るほど危険が増す」という本作の芯（切羽圧）を水でもう一度言い直すことになる。

**盤面の検査**（`tools/hostsim/sim.c`）

- `wet` — 落盤から60秒で水になった升の数。**10以上を必須**にしてある。
  少ないと「水が湧いた」ことが遊びに関与しない（敵の巣や岩で水路が塞がって3升で止まる種があった）
- `wseal` — 四方が全部水になって叩けなくなった黒ダイヤの数。**0が必須**（詰み防止）
- `tools/hostsim/sim --stage 7 --water` で、落盤後の盤面を升で出せる

**速さ**（openMSX、Z80 3.58MHz、面7で実測）

| | fps |
|---|---|
| 落盤だけ（湧き出し口を無効化） | 56.5 |
| 落盤＋出水（広がっている間） | 51.5 |
| 広がり終わったあと | 60.0 |

**広がり先を探すのに盤面176升を3周していたときは、1秒ごとに約80ms 食って 49fps まで
落ちていた。** 水は最大24升しか無いので、**水になった升だけを覚えて、そこだけ見る**
ようにした。水を描くときも升をまるごと描き直さず、坑道の上にタイルを重ねるだけにした。

**いまは面7だけ**（`WATER_ST`）。体感を見てから第三坑（面7〜9）へ広げる。

**実機での確認**（openMSX）: 炭柱を割ると湧き出し口から水が出て1秒に1升ずつ広がること、
熱水に浸かると体温が毎秒約40上がること（0から約6秒でオーバーヒート）、
水風呂と敵の巣が水没しないこと、面の開始から湧き出し口の絵が出ていること。

## 7c. 溜まり湯 ── 第四坑からの置き物（2026-09-26）

**面の開始から坑道に溜まっていて、最初から止まっている熱水。**
湧き出し口の水（§7b）と違って**広がらない**。作者の案「後半面の難易度調整のための
アイテムとして、最初からせき止められた状態で水があってもよい」。

| | |
|---|---|
| どの面 | **面10から**（`WPOOL_ST`）。面10・11 = 1升、面12・13 = 2升、面14・15 = 3升（`WPOOL_MAX`） |
| どこに | 面の開始から掘れている坑道の升。**出発点から4升以上**、**水風呂と敵の巣から3升以上**離す |
| 見た目 | §7b の熱水と同じ（青い湯・赤く熱した水面・湯気）。ただし**縁の開いている面すべてに岩の色の帯（3px）が最初から付いている** |
| 動き | **増えない・減らない。** 湧き出し口も無い |
| 浸かると | §7b と同じ。**体温が毎フレーム +1**（実測で毎秒 +43。浸かっていなければ +4） |
| 敵 | **入らない**（§7b と同じ） |

**印の意味を一貫させてある。** 岩の色の帯は「**ここから先へは水は来ない**」の意味で、
面7で水が止まったときに出るものと同じ。第三坑でその読み方を覚えていれば、
第四坑の溜まり湯は**見ただけで「これはもう増えない」と分かる**。

**置き方の条件**（`place_pool()`、`src/field.c`）

- **敵が巣から出発点まで来られなくなる升には置かない。** 敵は熱水に入れないので、
  坑道の一本道に置くと敵が一体も出て来られず、面が骨抜きになる。
  置いてから巣を起点に塗り潰し（`flood_from`、熱水を壁として扱う）、届かなければ取り消す
- **隣の黒ダイヤを「湯に浸からないと叩けない」状態にしない**（`coal_dry_ok()`）。
  四方が水と黒ダイヤだけになった黒ダイヤは、浸かり続けないと採れない。
  「採掘は妨げない」を溜まり湯にも課している
- **樋の落とし口は塞がない**

**盤面は動かない。** 置く工程を独立した種（`PH_POOL`）にしてあるので、
**面9までの盤面はこの機構を入れる前とまったく同じ**。15面すべてが今まで通り
`pick_seeds` の必須条件と狙いを満たしている（`pool` 列で升数を確認できる）。

**掘ったら印を引き直す。** 溜まり湯の隣を掘ると、その面が「坑道が続いているのに
水が来ない面」に変わるので、`dig_sweep()` が隣の熱水を描き直す。

**実機での確認**（openMSX）: 面12 で溜まり湯が2升 置かれ、湧き出し口は無く、
水風呂が健在であること（`tools/smoketest.sh`）。溜まり湯の升に立つと体温が1秒で +43、
外へ出ると +4 に戻ること。VRAM を読んで、縁の開いている面すべてに岩の色の帯が出ていること。

## 8. 土の膜（重要）

掘り跡は升の内側12×12pxだけを抜くので、**隣り合う坑道の間に2pxの土の膜が残る**ことがある。
この膜は**見た目だけでなく本物の壁**で、升と升の境目ごとに「抜けているか」を持っている
（`cell_link[]`）。

- 面の最初から掘れている升どうしは繋がっている扱い
- 後から抜けるのは、**自機の掘り跡が実際にその境目を跨いだとき**、
  **黒ダイヤが割れたとき**、**岩が落下で縦に突き破ったとき**
- 敵はこれを歩いて抜けられない（透明化するしかない＝遅くなる）

**この仕組みが敵の圧を大きく下げている。**（かつて「敵が1升以内に居る時間 78% → 59%」と
記録していたが、あれはユークリッド距離で測っており危険を過大に見ていた。
正しくは通行グラフ上の距離で測る。`docs/HOSTSIM.md` 参照）

### 5幕15面 ── 坑の深さと番方（2026-09-20）

**15面を3面ずつ5つの幕に区切ってある。**「3面で1日（一番方・二番方・三番方）が回り、
3日ごとに1つ深い坑へ降りる」という構造。史実では坑内は3交代で24時間動き、常磐の炭層は
海側へ傾斜していて深いほど条件が悪かった（`docs/HISTORY.md` §5.3・§6）。

| | 面1〜3 | 面4〜6 | 面7〜9 | 面10〜12 | 面13〜15 |
|---|---|---|---|---|---|
| 幕 | 第一坑 | 第二坑 | 第三坑 | 第四坑 | 第五坑 |
| 土の色 | 茶 (4,2,1) | 灰 (3,3,2) | 青 (2,2,4) | 藍 (2,1,3) | 闇 (1,1,2) |
| **増えるもの** | **―**（掘る・岩・炭柱・落盤） | **樋** | **出水**（面7で試験中） | **溜まり湯**（§7c） | **溜まり湯**（3升） |

- 面の開始表示は **「第 n 坑 m 番方」**（以前は「第 n 階層 開始」）
- **HUD の帯の色は番方で変わる**（一番方=朝 (1,2,2) / 二番方=昼 (2,2,1) / 三番方=夜 (1,1,3)）。
  どれも暗いままにして白と黄の文字が読めるようにしてある
- 土の色は以前**3面ごと**の繰り返しだったので、面2 と面11 が同じ色だった。

### 盤面の難易度の設計（2026-09-09 に作り替え）

**盤面は `src/field.c` の `stage_seed[]` で面ごとに固定してある。**
種は総当たりして選んだ（`tools/hostsim/pick_seeds.py`）。

**指標を作り替えた（2026-09-10）。** 横移動を**樋**へ集約したので、岩は炭層の
**真上**へ戻した（`place_rocks()` は `keep_above_coal()` を最優先にする）。
樋は岩と炭層の位置が決まったあと、**岩の列の下**へ置く。

| 指標 | 意味 |
|---|---|
| **`hand`** | **つるはしを1本入れるだけで採れる黒ダイヤの数（掘らない）。難易度の軸** |
| **`hpick`** | **炭柱以外の1枚を割って、岩が樋を通って採れた数。指でなぞれる線の保証** |
| `hbend` | `hand` の最善手の中で岩が樋を通った回数。**1以上を必須** |
| `taken` | 炭柱を叩いて落盤を起こしたときに採れる数（`hand` の候補のひとつ） |
| `reach` | 炭以外を全部掘ったうえでの、1回の落下で採れる最大数（上限の参考値） |
| `free` | 岩の真下の黒ダイヤ数＝何もしなくても手に入る連鎖の長さ |

**軸を `reach` から `hand` へ移した（2026-09-12）。** `reach` は「掘りたいだけ掘れたら」の
上限なので、**遊んだときに起きることを測っていなかった。** 盤面が「岩→炭層→樋→炭柱」と
並んでいても、途中が土で塞がっていれば岩は止まる。実際に面1がそれで、
作者に「ルールおかしくない？」と指摘されて発覚した（§6.4 の記録）。

`hand` は**盤面をそのまま使い、黒ダイヤ1枚だけを耐久ぶん叩いて engine を回す。**
盤面上の全部の黒ダイヤを順に試して一番良い結果を採る（どれを叩くかはプレイヤーが
選べるため）。炭柱を叩いた場合の落盤もこの中に含まれる。

**`hand` だけでは足りなかった。** 取れ高で選ぶと最善手が毎回「炭柱を叩いて落盤」に
なり、**樋が一度も使われない面**が選ばれた。さらに `hbend`（最善手の中で樋を通った
回数）を足しても、通るのは落盤で降ってきた岩で、**原因が盤面全体なので目で追えない。**

そこで **`hpick`**（炭柱以外の1枚を割って、岩が樋を通って採れた数）を必須条件にした。
普通の黒ダイヤ1枚なら「この岩が落ちて、この板で曲がって、ここを採る」という
**一本の線**になり、落とす前に指でなぞれる。

| | 最低 `hpick` |
|---|---|
| 面1〜3（教材） | **4** |
| 面4〜9 | **3** |
| 面10〜15 | **2** |

**ずらして置く岩を足した（2026-09-16）→ 準備の見返りを主軸にした（2026-09-19）。**
面が進むと岩の一部を炭層の真上からずらして置く（§6.5）。**何個か動かして準備してから
一気に採る**のが狙いなので、押さない一手の取れ高 `hand` は小さめの目安にとどめ、
**全部揃えてからの取れ高 `hprep` が大きい盤面**を選ぶ。

| 指標 | 意味 |
|---|---|
| `npush` | ずらした岩のうち、左右へ1〜2升押せば黒ダイヤの真上で止まる数（engine で実際に押す） |
| `hpush` | **1つ**押して揃え、一手打って採れる最大数。一手は真下を割る／炭柱を割るの良いほう |
| **`hprep`** | **ずらした岩を全部揃えてから炭柱を割って採れる数。準備の見返り** |
| `cbal` / `rbal` | 左右の散らばり。少ない側の黒ダイヤ／岩の割合（%） |
| `rowdup` | 岩が2個以上ある行の数。**全面で0が必須** |

### 置く工程ごとに種を分けてある（2026-09-11）

**乱数は1本の流れなので、途中の工程が食う回数が変わると、それより後の工程が全部ずれる。**
実際に樋の置き方を書き直したとき、樋しか触っていないのに面11の盤面が必須条件を割った。

そこで `set_stage_layout()` は**工程ごとに種を振り直す**（`phase_seed()`）。

```
面番号の掘り抜き → 出発点 → [種1] 湧き出し口 → 風呂 → 通路を繋ぐ
→ [種2] 火薬 → [種3] 黒ダイヤ → [種4] 岩 → [種5] 炭柱 → [種6] 樋
```

種は `layout_seed() + 工程番号 x 0x9E37` なので、**「盤面は面番号だけで決まる」は変わらない。**

効果を対照実験で確かめてある。**火薬の数だけを 10→11 に変えて、他の配置が動くかを見た。**

| | 動いた配列（全15面） |
|---|---|
| 1本の流れ（従来） | `POWDER` `COAL` `ROCK` `PILLAR` `CHUTE` — 全部 |
| **工程ごとの種（いま）** | **`POWDER` だけ** |

**ただし工程間のデータ依存は残る。** 岩は黒ダイヤの真上へ寄せ、樋は岩の列の下へ置くので、
**黒ダイヤの配置を変えれば岩と樋は動く。** 動かないのは「乱数の流れがずれることによる
無関係な移動」だけで、そこが読めれば十分。

- **面の配置は面番号だけで決まる。毎回同じ盤面になる**（2026-09-04 に変更）。

## 12. 音

- **タイトル BGM**: Down in a Coal Mine（1872年、著作権切れ）。PSG3声
- **ゲーム BGM**: 常磐炭坑節。PSG3声（旋律／ベース／ノイズドラム）
- 効果音は ch C を一時的に奪って鳴らす（優先度つき）。**16種**:
  掘る／拾う／投げる／爆発／ミス／つるはし（キン）／投げられない／破砕／採掘（チャリーン）／
  **落盤**／**岩の境目（カチッ）**／**樋の板（バキッ）**／**熱水の噴き出し（ゴボッ）**／**熱水の滴（ポチャ）**／**湧き出し口が止まった（シュウ…）**／
  **クリア時の時間の刻み（チチチ）**。
  範囲判定は `SFX_N` で書く。以前は `id > SFX_COAL` と特定の音の名前で書いてあり、
  **あとから足した落盤の音が一度も鳴らないままだった**（2026-09-06 に修正）
- **ジングル**（曲を止めてトーン3声で鳴らす）は3つ: **クリアのファンファーレ**／
  **ミス**／**残り30秒の合図**（2026-09-26）。最後のは同じ音を刻みながら上がる約0.8秒の形で、
  祝いに聞こえないよう**伸ばさずに切る**。鳴り終わったら坑内の曲へ戻す（`snd_idle()` で
  終わりを見て `snd_play_bgm()`。曲は頭から鳴り直すので「後半が始まった」合図にもなる）
- PSG は矩形波固定。金属音はトーンとノイズを同じチャンネルに重ねて作っている
- **体温が上がるほど曲が速くなる**（2026-09-06 追加）。`TEMPO_T1` 120 / `TEMPO_T2` 180 /
  `TEMPO_T3` 216 の3段で、`TEMPO_UNIT` 16 分の 18 / 20 / 22（＝1.13 / 1.25 / 1.38倍）。
  **体温は本作の制限時間そのものなのに、表現が16目盛りのメーターしか無かった。**
  水風呂で冷えれば戻るので、そのまま解放の合図にもなる。**新しい音は1つも要らない。**
  1ティックの進みを 16分のn で数え、溜まったぶんだけ曲を進める（`music_step`）ので
  小節の頭を待つ必要が無く、どこで倍率が変わっても曲は繋がったまま速くなる。
  **遊んでいる間だけ効く**（体温は面をまたいで残るので、外すとクリアのファンファーレや
  タイトル曲まで速くなる）
- **音は実時間で進める。** ゲームループ1周につき1回ではなく、JIFFY の差分から
  経過フレーム数を割り出して追いつかせている。掘っている間は 60fps を割るので、
  1周1回だと**曲のテンポが遅くなっていた**（掘っている間は本来の72%）

## 13b. ジュースを提案するときの技術的な制約

**ここを外した案は入らない。** 数値は openMSX での実測（2026-09-05）。

### 速度：ボトルネックは VDP であって CPU ではない

| 状態 | fps |
|---|---|
| 止まっている | 60.0 |
| 掘っている | 56.0 |
| 坑道を移動している | 52.0 |

**計算ではなく VRAM への書き込みが律速。** 「高速 CPU が何とかしてくれる」は当てはまらない。

**turbo R についての事実（2026-09-12 に調べ直した）。**

| | |
|---|---|
| いまの動作 | カートリッジは必ず Z80 モードで起動する。`CHGCPU` (0x0180) を自分で呼ばない限り R800 にならない。**このゲームは `main()` の冒頭で呼んでいる**（`msxver() >= 3` のときだけ `CPU_R800D`。本体の LED も変える）。**実機の turbo R では R800 DRAM モードで動く**（2026-09-12 に入れた。それ以前は Z80 のままだった） |
| R800 にすると速くなるもの | **内蔵 DRAM にあるものだけ。** R800 DRAM モードでは内蔵 BIOS ROM が DRAM へ写るので、BIOS 呼び出しと割り込み処理が速くなる。`RAMCODE` (0xD000) も速くなる |
| 速くならないもの | **カートリッジスロットのクロックは常に 3.58MHz。** S1990 が外部スロットと I/O アクセスに wait を入れる。**VDP は I/O なので律速は変わらない** |
| 切り替えるときの危険 | R800 は OUT が連続すると VDP が追いつかないと言われるが、**VDP は I/O なので S1990 が wait を入れる**（さらに VDP I/O には追加の wait が入る）。**だから `vdp_wblock` の OTIR もそのまま安全**（`src/main.c` の説明） |

**turbo R で実測できるようになった**（2026-10-01）。作者が自分の FS-A1ST から
ファームウェアを吸い出してマシン定義を作ったので、openMSX で turbo R が動く。

```
openmsx -machine My_FS-A1ST_512K -carta build/sakiyama.rom -romtype ASCII8
MACHINE=My_FS-A1ST_512K sh tools/smoketest.sh build/sakiyama.rom   # 実機 BIOS でも PASS
```

**測った結果**（面7・10秒・操作なし。`frame_n` の増分を数えた）

| 機械 / CPU | 陽炎なし | 陽炎あり |
|---|---|---|
| **turbo R 実機BIOS / R800 DRAM**（出荷する形） | **59.9** | **59.9** |
| turbo R 実機BIOS / Z80 3.58MHz | 55.7 | 38.6 |
| C-BIOS MSX2+ / Z80 3.58MHz | 55.8 | 44.6 |

- **`CHGCPU` が効いていることの証明。** 同じ機械・同じ ROM で、`chgcpu()` の呼び出しを
  消したものと比べた（59.9 → 55.7）。**R800 DRAM モードで走っている**
- **turbo R では陽炎がタダ**（59.9 → 59.9）。Z80 では17fps 食う
- **実機 BIOS のほうが C-BIOS より陽炎が高い**（38.6 対 44.6）。**重いのは自前の処理ではなく
  BIOS が割り込み源を判定するまでの往復**という説明（§「速度」）の裏付けになっている
- 作者が実機で測った数字は 57/56fps だった。**openMSX のほうが少し良く出る**ので、
  実機の数字を上限とみなすこと

### タダに近いもの / 高いもの

|---|---|
| **パレット操作**（R#16/17）。数バイトで画面全体の色が変わる | 背景への描き足し |
| **画面揺れ**（R#18 SET ADJUST）。縦横とも動く | 広い塗りつぶし |
| **ヒットストップ**（数フレーム止めるだけ） | 大きなエフェクト画像 |
| **PSG**（音量・音程・ノイズ）。数バイト | スプライトの絵の差し替え（VRAM 転送） |
| スプライトの座標移動（OAM は128バイト） | |

**いちばん費用対効果が高いのはパレットです。** 1ドットも描かずに画面全体が反応する。

### ROM / RAM の空き

| 置き場 | 空き |
|---|---|
| 固定領域 0x4000-0x9FFF (24KB) | **157 バイト** |
| バンク窓 0xA000-0xBFFF (8KB) | **118 バイト** |
| RAM 実行 0xCD00-0xF1FF (9.25KB) | **55 バイト**（いま `enemy` `bomb` `sound` `title` `vdp` `text` `tlimit`） |

**3つとも残りわずか（合計300バイトほど）。次に何か足す前に置き場を組み直すこと。**

（2026-09-26: **RAM 実行の上端を 0xEFFF から 0xF1FF へ広げた（+512 バイト）。**
スタックがどこまで伸びるかを実測して決めた: 0xEF60 以降を 0xA5 で埋めてから、タイトル・
面の組み立て・3分半の実プレイを通して最低到達点を読むと **0xF30F**（0xF380 から113バイト）。
0xF200 との余裕は271バイト。制限時間の `tlimit` はここへ置いた。

（2026-09-26: 溜まり湯（§7c）で固定領域が 803 → 175 バイトまで減った。
**次にギミックを足す前に置き場を広げること。** 候補は、面を組む処理（`place_*`）を
別ファイルにしてバンク窓か RAM 実行へ移すか、RAM 実行の上端を 0xEFFF から広げる
かのどちらか（スタックとの余裕は実測してから決める））

（2026-09-23: RAM 実行の領域を **0xCD00-0xEFFF（8.75KB）**まで広げ、`text` も移した。
**8KB を超えたので ROM のセグメントは2枚**になり、起動時の写しも2回に分かれる（`main()` の冒頭）。
変数との余裕は約110バイト、スタックとの余裕は約880バイト。
変数が伸びて RAM 実行の領域に食い込んだら `tools/ihx2rom.py` が止める。
RAM はバンク窓の切り替えの影響を受けないので、タイトル画像を読む最中に呼ばれるものも置ける）

（2026-09-20 実測。ギミックを足す置き場を作るため `sound` を RAM 実行へ移し、固定領域を 153 → 1958 バイトへ戻した。
RAM 側はほぼ満杯なので、次に空けるときは **RAM 実行の領域を下へ広げる**（変数は 0xC000 から約2.5KB しか使っていない）か、
**バンクのセグメントを増やす**（窓の切り替えが要る）ことになる）

置き方は `CLAUDE.md` を参照。**「ROM に入らない」と言う前に、どの窓が詰まっているかを区別すること。**

## 16. 【決着済みの記録】岩・炭柱・落盤が遊びに繋がっていなかった件

**2026-09-01 時点の相談事項。解決したので記録として残す。**

### 何が起きていたか

仕掛け（§6）は全部入っていたのに、遊んでいて活きてこなかった。
`tools/hostsim` の貪欲ボットで12回ずつ走らせ、**盤面の岩が一度でも動いたか**を数えた
ところ、**面5以降は 100% の試行で岩が一度も動かなかった**（面1でも94%）。
まとめて潰すほど跳ねる得点表（Dig Dug の 1000/2500/4000/6000/8000 とほぼ同じ比率）が
**一度も使われていなかった。**

> 数字にはボットの限界も含む。貪欲ボットは面3以降をクリアできず炭柱まで届かない。
> ただし「一番近い黒ダイヤから順に掘る」という素直な遊び方で岩に触らないこと自体が
> 問題だった。

### 何をしたか

| | 変更 | 効果 |
|---|---|---|
| ① | **岩を黒ダイヤの真上へ置く** | 掘れば岩が動く。「触らない」が構造的に起きなくなった |
| ③ | **落盤で画面全体を白く飛ばす** | 見ていない場所で起きた事件が伝わる |
| ④ | **落盤を「岩の下の黒ダイヤが一斉に割れる」に変える** | 沈むだけでは何も起きなかった |
| — | **落ちる岩が黒ダイヤを突き抜けて採る**（作者の指摘） | ここが決め手 |
| — | **連鎖を時間で繋ぐ**（作者の指摘） | 岩の採取と自分の採取が同じ連鎖になった |
| — | **かけらが自機へ集まる**（作者の指摘） | 仕掛けを絵で説明できるようになった |

**②（落盤で全敵よろけ）も実装済み。** 1段（2秒）。位置合わせが要らないので
落ちてくる岩の命中率が上がる。

### 途中で潰した詰み

- **炭柱を割ると詰む面があった。** 岩は2升以上落ちないと割れないので、炭柱を割って
  1升だけ落ちた岩が、割れた黒ダイヤの上に居座って永久に採れなくなっていた。
  `coal_crush_at` で自動回収するようにして解消
- **岩が黒ダイヤを素通りして沈んでいた**（別の詰み）
- **連鎖採掘で閃きが消えず白い升が残っていた**（記録用の変数が1個しか無かった）
- **黒ダイヤの得点表示が一度も見えていなかった**（描いた直後に升の再描画で消していた）

### 結論

作者の評価は **「あー気持ちいいですねーこれが求めていた爽快感」**。
以後の設計は「岩を落として鉱脈を貫かせ、連鎖が切れないうちに自分でも採りに走る」を
中心に置く。

## 16b. その他の既知の弱点

### 爽快感について

**§16 で決着した**（岩を黒ダイヤの真上へ置き、岩が突き抜けて採り、連鎖を時間で繋いだ）。
以下は残っている論点。

1. **落盤の敵一掃は、いまだにプレイヤー自身が思いつかないと発生しない。**
   「先に縦穴を掘っておく」という事前準備が要る。②（全敵よろけ）で位置合わせは
   不要になったが、**偶発的に起きるところまでは行っていない**
2. **報酬が数字であって、状態の変化ではない**

### 設計上の弱さ

3. **ボーナスは黒ダイヤに関係しない**ので寄り道の理由が弱い
4. **序盤（面1〜7）が簡単すぎる**という体感がある

### 仕様の一貫性が微妙な点

6. 割れた黒ダイヤは**その升に入らないと採掘できない**（割った瞬間ではない）。
   **これは意図した駆け引き。** ただし**落ちる岩だけは例外**で、突き抜けた升をその場で採る
7. **地中を透明で移動している敵にはダイナマイトが当たらない**（坑道しか飛ばないため）。
   **つるはしは当たる**（2026-09-04 に変更。透明の間まで無敵だと、こちらは手も足も
   出ずに待つしかなく、ただのストレスになっていた）

### 速度

8. **掘っている間は 55fps**（Z80 3.58MHz / openMSX の C-BIOS MSX2+ で実測）。
   **turbo R（R800 DRAM モード）では 60fps**（2026-10-01、実機 BIOS で実測）。

   **陽炎のコストは機種で全く違う**（2026-09-12 実測）。

   | | 陽炎なし | 陽炎あり |
   |---|---|---|
   | Z80 3.58MHz（C-BIOS MSX2+） | 55 | **44** |
   | Z80 3.58MHz（turbo R の実機 BIOS） | 56 | **39** |
   | **turbo R / R800 DRAM**（出荷する形） | **60** | **60** |

   （2026-10-01 に openMSX の turbo R 実機 BIOS で測り直した。§13b に測り方と
   `CHGCPU` が効いていることの確かめ方がある。作者の実機では 57/56 だった）

   V9938 のライン割り込みを1画面12回使うが、**重いのは自前の処理ではなく
   MSX BIOS が割り込み源を判定するまでの往復**。その BIOS は内蔵 ROM にあるので、
   **R800 DRAM モードでは DRAM へ写って一気に軽くなる**（作者の turbo R 実機で確認）。
   Z80 機では分割1本につき約1.4 fps（12回で 55→44 / 8回で 49.5 / 6回で 52 / 4回で 54.7）。

   **陽炎なしの fps が 55→57 とほとんど変わらないのも同じ理屈。**
   律速は VDP への書き込み＝I/O で、S1990 が wait を入れるので R800 でも速くならない。
   **「速くなるのは内蔵 DRAM にあるものだけ」**がそのまま数字に出ている。
   **面の組み立てで画面を落としている時間は 2.4〜2.6秒**（2026-09-11 実測）。
   ほとんどが `set_stage_layout()` の候補探しで、**樋の導入ぶんは +0.4秒**
   （導入前 2.06秒 → 2.45秒。`place_chutes()` が候補一覧を板1枚ごとに作り直して
   いたときは +1秒近くあり、列ごとの岩の表を先に作る形へ直した）。
   コンフィグ画面を描く時間も同じ理由で 1.6秒ある。タイル描画を1行ずつの一括転送に変えて 32 → 46 まで上げ、
   さらに `enemy` `rock` を **RAM 実行へ移したことで 56 まで上がった**。
   ボトルネックは計算ではなく **VDP への書き込み**で、
   **R800 に切り替えても VRAM の待ち時間は変わらない**ので、ここから先は伸びにくい

### 技術的な制約

9. **置き場は3つ。いまの空きは合計 約4.9KB**（2026-09-10 実測）。

   | 置き場 | 使用 | 空き |
   |---|---|---|
   | 固定領域 0x4000-0x9FFF (24KB) | 23332 | **1244** |
   | バンク窓 0xA000-0xBFFF seg3 (8KB) | 7256 | **936** |
   | **RAM 0xD000-0xEDFF (7.5KB)** | 5138 | **2542**（いま `enemy` だけ） |

   **0x4000-0xBFFF の 32KB は「同時に見えている量」の上限**で、並べ替えでは増えない。
   ROM を 128KB にしても変わらない。そこで**起動時に ROM から RAM へコードを写し、
   RAM で実行する**方式を入れた（`enemy` / `rock`）。逃がし方は `CLAUDE.md` を参照。

   RAM が空いている根拠は openMSX の実測。ページ3 のうち変数が 0xC000 から約2.5KB、
   **スタックは 0xF380 から下へ約350バイトしか伸びない。**
10. **スプライトは横一列に8枚まで。** 9枚目以降は消える。いま22面使っている
    （自機1・爆弾1・岩8・敵6・かけら6）。**岩を1行1個に制限しているのはこのため**
11. **スプライトは1行1色。** 自機につるはしを持たせられないのはこれが理由
