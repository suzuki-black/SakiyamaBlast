# 絵とアニメーションの一覧（現状）

**キャラを描き替える前に「何枚必要か」を決めるための資料。**
いま何が何枚あって、どの状態でどれが出るかを、コードから起こしたもの。

- 絵の正: `assets/sprites.png` / `assets/tiles.png`（PNG が正。`make` で C へ変換）
- 名前の並び: `Makefile` の `ART_SPR_NAMES` / `ART_TILE_NAMES`
- 番号の定義: `src/game.h` の `PAT_*` / `src/art.h` の `TILE_*`
- 往復編集: `make gamedata` → `gamedata.json` → `make gamedata-import`（`docs/GAMEDATA_FORMAT.md`）

> **`gamedata.json` は 2026-09-01 生成のままで古い。** 「各キャラ1枚しか絵が無い」と
> 書いてあるが、いまは自機だけで17枚ある。描き替え前に `make gamedata` で作り直すこと。

## 1. スプライト（全26枚）

**16×16 / 1面1枚 / mode 2（1行1色）。** いま32面のうち **22面**を使っている
（自機1・爆弾1・岩8・敵6・かけら6）。

### 自機「丹野3時」— 17枚

| 状態 | 枚数 | パターン | コマ送り |
|---|---|---|---|
| 正面 | 1 | `PAT_MINER` | **面の開始時、まだ一度も動いていない間だけ。** 以後は出ない |
| 歩き | **8**（4方向×2） | `PAT_WU1/2` `PAT_WD1/2` `PAT_WL1/2` `PAT_WR1/2` | `WALK_FRAMES` **8フレームごと**に2コマを交互。**止まっていてもコマ1で立ち姿**として使う |
| 溜めの構え | **4**（4方向） | `PAT_BRU` `PAT_BRACE`(下) `PAT_BRL` `PAT_BRR` | **1方向1枚。** 溜めの段（1〜3）では絵を変えない。段の差は**背景の汗**で出している |
| 振り下ろし | **4**（4方向） | `PAT_STU` `PAT_STD` `PAT_STL` `PAT_STR` | **1方向1枚。** 振っている `PICK_FRAMES` 18フレームずっと同じ絵。**振りの動きは背景のつるはし（3段）**で出している |

**選び方**（`player_pattern()`）:

```
まだ動いていない or 向き未定 -> 正面
振っている                   -> 振り下ろし[向き]
溜めが2段以上               -> 構え[向き]
それ以外                     -> 歩き[向き][コマ]
```

### 敵 — 4枚

| 状態 | 枚数 | パターン | コマ送り |
|---|---|---|---|
| 通常 | **1** | `PAT_RAT` | **無し。4方向とも同じ絵、歩きのコマも無い** |
| よろけ | **3** | `PAT_STUN1/2/3` | 段（1〜3）で切り替え。時間で1段ずつ戻る |
| 透明化中 | 0 | （`PAT_RAT` のまま） | **色だけ抜く。** 予兆は**2フレームごとの点滅**（絵は変えない） |

**4種類の敵は色だけが違う。** 色は狙う升の決め方（アルゴリズム）を表す情報なので、
**状態表示に色を使ってはいけない**。

## 3. 絵を持たず、背景に手続きで描くもの

**ここはパターン数に数えない。** 描き替えの対象外だが、
**スプライトのコマ数を決めるときに関係する**ので載せる。

| もの | どこ | コマ数 | なぜスプライトでないか |
|---|---|---|---|
| **つるはし（振り）** | `draw_swing_fx` | **3段**（`PICK_FRAMES` 18 を3分割） | 自機のスプライトは16×16がほぼ埋まっていて、**1行1色**なので持たせる余地が無い。面を増やすと横一列8枚の制限に触れる |
| **汗（溜め）** | `draw_charge_fx` | 段（1〜3）ごと | 同上 |
| 水風呂の泡 | `draw_bath_active` | **8コマ**（上がって戻る） | 位置が固定で、面を使う価値が無い |
| 土 / 坑道 | `draw_cell_dirt` `draw_dug_cell` | — | 矩形塗り。隣が掘れているかで形が変わる |
| 黒ダイヤの耐久数字 | `draw_coal` | — | BIOS フォント |
| 得点ポップアップ | `score_popup` | — | 同上。800点以上は倍角 |
| 採掘の閃き | `take_one` → `coal_shake_tick` | 白 → 水色 → 元 | 升を塗るだけ |
| 面の開始「第 n 階層 開始」 | `kanji_draw` | — | 自前の16×16を15字（`docs/KANJI_FORMAT.md`） |

**溜めと振りの最中は自機が必ず静止している**ので、背景に描いて離れるときに消せる。
これが「1方向1枚で足りている」理由。

## 4. 増やすときの制約と予算

### 数の制約

| 制約 | 値 | 効くところ |
|---|---|---|
| スプライト面 | 32面中 **22面使用**（残り10面） | 同時に出せる数 |
| **横一列** | **8枚まで。9枚目以降は消える** | 岩を「1行に1個」に制限している理由 |
| **1行1色** | mode 2 | 自機につるはしを持たせられない理由 |
| 色 | 512色中16色 | パレットは面ごとに差し替え可 |

### ROM の予算（バンク窓 0xA000、いま 6592/8192＝**空き1600バイト**）

| 足すもの | 1枚あたり | 空き1600バイトで |
|---|---|---|
| スプライト1枚 | **48バイト**（絵32＋行ごとの色16） | **約33枚** |
| タイル1枚 | **128バイト** | **約12枚** |

**枚数は当面の制約ではない。** 33枚足せるので、たとえば
「歩きを2コマ→3コマ（4方向で+4枚）」「構えを段ごとに（+8枚）」
「振りを3コマに（+8枚）」を全部やっても入る。

> 窓が足りなくなったら `CLAUDE.md` の「逃がし先は3つある」を参照。
> **絵は固定領域に置かない。**

## 6. 描き替えの手順

```bash
make gamedata          # assets/*.png -> gamedata.json (まず作り直す)
# gamedata.json の pixels をエディタで編集、または assets/*.png を直接描き替え
make gamedata-import   # gamedata.json -> assets/*.png
make                   # PNG -> C -> ROM
```

**枚数を増やすときは `Makefile` の `ART_SPR_NAMES` に名前を足し、
`src/game.h` に `PAT_*` を足す**（並び順を一致させること）。
`ART_SPR_N` は生成側が出すので、転送漏れは起きない。
