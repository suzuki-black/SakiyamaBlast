面の開始に出す「第 X 坑 Y 番方」の字は、`tools/mkkanji.py` の中に**ドット絵**として
書いてある。ここを描き替えて `make` すれば差し替わる。C のコードには触らなくてよい。

## 描いてほしいもの

| 字 | 状態 |
|---|---|
**いまは18字すべて実装側で描いてある**（第・坑・番・方・開・始・階・層＋漢数字一〜十）。 外部に頼む必要はもう無い。

## 描くときのコツ（一度失敗して分かったこと）

- **画数の多い字は線 1px。** 第・階・層・開・始 を線 2〜3px で描いたら、
  全部潰れて読めなかった。16x16 は昔の漢字ROM と同じ土俵で、あの細さが正解。
  画数の少ない漢数字だけ 2px にして、番号が目立つようにしてある
- **線と地を反転させない。** 外注で戻ってきた画像は、字を黒で描くのではなく
  「黒い塊の中に線の隙間を白く抜いた絵」になっていて、まったく使えなかった
- **目で見ながら直す。** 頭の中だけで 16x16 のドットを組んでも当たらない。

```bash
python3 tools/mkkanji.py --preview /tmp/prev.png
```

で18字を拡大画像に起こせる。これを見て直す、を繰り返すのが唯一の近道。

```bash
python3 tools/mkkanji.py --write   # src/kanji.c の表を差し替える
```

## いちばん大事な約束

**16×16 のマス目に正確に乗せ、字面をマス目いっぱいに使うこと。**

一度もらった画像は、墨のある範囲が 707×639 px だった。横は 1マス44px の 16マス
ぴったりだったが、縦は 14.5 マスぶんしかなく、さらにブロックの境目が 32px・20px・
10px とまちまちで、「ドット絵風の絵」であってドット絵になっていなかった。
どう格子を当てても崩れる。

- **1マスは必ず同じ大きさ**（例: 1マス 32px なら画像は 512×512 ちょうど）
- **上下左右の端まで使う**。余白を大きく取ると 16×16 に落とすとき位置が定まらない
- 中間色を使わない。**2色だけ**

## 形式

**16×16 の 1bpp。** `#` が字、`.` が余白。**16行ちょうど、各行16文字ちょうど。**
これ以外の文字は使えない（スクリプトが弾く）。

```python
G['第'] = [
"...##......##...",
"...##......##...",
"..####....####..",
"################",
"..##......##....",
"................",
".##############.",
".##..........##.",
".##############.",
".##..........##.",
".##############.",
"......####......",
"......#..#......",
"....######......",
"......##........",
".....##.........",
]
```

## 決まりごと

- **並び順は変えない。** `order = ['第','階','層','開','始','一',…,'十']` は
  `src/game.h` の `KJ_*` と一致している必要がある
- **1文字あたり32バイト**。15文字で480バイト。ROM のバンク側に置いてあり、
  いまの空きは約350バイトなので、**字数を増やすと入らない**
- 表示は 16×16 をそのまま等倍で出す。拡大や縮小はしない
- 色は字が1色、下地が1色。**アンチエイリアスや中間色は使えない**
- 字面の狙いは「古くさい写植のような重い線」。細い線は 16×16 では潰れる

## 画像で渡してもらう場合

ドット絵のテキストではなく **PNG 画像**で描いてもらってもよい。取り込む道具がある。

```bash
python3 tools/png2kanji.py 画像.png 第 --patch
```

画像の大きさ・色数は問わない。明るさで二値化し、字のある範囲を切り出して 16x16 に
均し、`tools/mkkanji.py` の該当の字を書き換える。`--patch` を付けなければ結果を
表示するだけなので、まず目で見てから入れられる。「Made with AI」の札は右上として
既定で無視する（`--badge 0` で無効）。

**画数の多い字は字面いっぱいに描いてもらうこと。** この道具は「字のある範囲」を
16x16 の枠に合わせるので、`一` `十` のように余白の広い字だと、意図した余白まで
復元できない（枠から外れると警告が出る）。余白のある字は `--no-square --pad` で
調整するか、ドット絵のテキストで直接もらうほうが早い。

しきいの調整:

| 旗 | 効き |
|---|---|
| `--thresh 0.6` | 薄い線も拾う（既定 0.5） |
| `--cover 0.4` | マスを塗る条件をゆるめる＝線が太くなる（既定 0.5） |
| `--pad 0.5` | 外へ 0.5 マスぶん余白を足す |
| `--no-square` | 縦横を別々に伸ばして枠いっぱいにする（字は歪む） |
| `--align start` | 正方形にするとき狭い側を上/左へ寄せる（既定は `center`） |
| `--shift 0,1` | 結果をマス単位でずらす |

## 確認のしかた

```bash
make            # 差し替えてビルド
make check      # 壊れていないか
```

画面での見え方は openMSX で VRAM を読めば確認できる（`docs/HOSTSIM.md` とは別に、
`debug read VRAM` で表示行 y=80..95 を見る）。
