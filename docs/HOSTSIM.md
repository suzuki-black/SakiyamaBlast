# 面の数値化ツール (tools/hostsim)

`src/` のゲームロジックを **そのまま gcc でビルド**し、VDP/PSG だけスタブに差し替えて
ヘッドレスで走らせる。面の当たり外れを数字にして、手で15面を調整する作業を減らすのが目的。

```bash
make hostsim                                  # ビルド
make grade                                    # 面1〜15を24回ずつ採点
tools/hostsim/metrics.py --stage 7 --runs 50  # 1面だけ詳しく
tools/hostsim/sim --stage 1 --seed 3          # 生ログ (JSONL) を見る
```

15面 × 24回で数秒。何百回でも回せる。

## 仕組み

| ファイル | 役割 |
|---|---|
| `tools/hostsim/stubs.c` | VDP・PSG・スプライト・文字・絵データのスタブ。入力もここからボットが注入する |
| `tools/hostsim/sim.c` | 通行グラフの BFS、ボット、毎フレームの JSONL 出力 |
| `tools/hostsim/metrics.py` | JSONL を読んで採点する。しきい値と合格条件はここ |

**ゲームのロジックには一切手を入れていない。** `field.c` / `enemy.c` / `player.c` /
`rock.c` / `bomb.c` / `bonus.c` を実機と同じソースのままリンクしている。

### 型を合わせてある

`src/msx.h` は `HOSTSIM` が定義されているとき `<stdint.h>` を使う。MSX 側は
`int` が16bitなので、ホストで32bitのまま走らせると**桁あふれの挙動が変わり、
シミュレーション結果が実機と食い違う**。

### 計測のために公開した変数

`en_morph` / `en_ghost` / `en_warm` は本来 static だが、透明化と点滅の状態が
読めないと危険度が測れないので公開している (`en_rest` と同じ扱い)。実行時の
コストは無い。

## 危険度の測り方

**ユークリッド距離では測らない。** `cell_link[]`（掘り跡に残る土の膜）があるため、
1升隣に居ても膜で隔てられていれば敵は来られない。危険度は必ず**通行グラフ上の距離**で測る。

- **到達余裕 `T_reach`** = 一番早く自機の升へ来られる敵の所要フレーム数。
  敵の速度は種類ごと (`SPD_RED`..`SPD_ORANGE`)、透明化中は `SPD_GHOST`。
  湧いて点滅中 (`en_warm`) の敵はまだ当たらないので除外する
- **退路数 `E`** = 隣の4方向のうち、そこへ動くと `T_reach` が増える向きの数。
  0 か 1 なら追い詰められている

## 指標

| 指標 | 定義 | 意味 |
|---|---|---|
| **ヒヤリ** | `T_reach` が1.0秒を下回った瞬間 | 緊張感の1単位 |
| **爽快** | ヒヤリが0.5秒以内に解消し、その間に得点が入った | 緊張を自分の手で解消した |
| **麻痺** | `T_reach` < 1.0秒 が5秒以上続く | 危険が常態化して意味を失っている |
| **凡死** | 退路0の状態でヒヤリに入った | 判断で避けられていない |
| **退屈** | 敵が3秒以上遠く、報酬も無い | 掘るだけの時間 |
| **放出量** | 0.3秒窓の (得点 + 鳴った効果音) のピーク | どれだけ派手に解消したか |

爽快感は「解消したか」(率) と「どれだけ派手に解消したか」(振幅) の掛け算。

## 使うときの約束

- **これは「面白さ」ではなく「面白さの必要条件の欠落」を測る道具。**
  ヒヤリ0回の面はつまらないと断言できるが、ヒヤリ5回の面が面白いとは断言できない。
  **否定側にだけ強い**
- **目的関数にしてはいけない (Goodhart の罠)。** ヒヤリ回数を最大化しにいくと
  「敵を増やして通路を狭くする」のが最適解になり、理不尽な面ができる。
  **合格/不合格のゲートとして使う**
- **しきい値はまだ較正していない。** 1.0秒 / 0.5秒 / 3.0秒 は暫定値で、
  人に遊んでもらって「ヒヤッとした瞬間」の申告と突き合わせて合わせる必要がある

## いまのボットの限界 (重要)

ボットは貪欲で、「体温が7割を超えたら風呂、でなければ一番近い黒ダイヤ」へ向かい、
進みたい方向が危険なら逃げるだけ。**面3以降はクリアできない。**

したがって:

- **面をまたいだ絶対値の比較には使えない。** 面10の数字が悪いのは、面10が悪いのか
  ボットが弱いのか区別がつかない
- **同じ面での前後比較には使える。** ルールを変える前と後を同じボットで測れば、
  差はルールの効果である
- **麻痺・凡死・詰みの検出は比較的信用できる。** ボットの強さにあまり依存しない

面をまたいだ比較をしたいなら、まずボットを強くすること (ダイナマイトを使わない、
岩を利用しない、先読みしない、といった穴がある)。

## 次にやること

- **順序依存度**: 炭層の採掘順を全探索し (面15でも 4! = 24通り)、クリア時間の
  変動係数を出す。0.05未満なら「掘る順序に意味が無い」。炭柱が効いたかの判定に使える
- **詰みの自動検出**: 岩が割れた黒ダイヤの升に居座ると回収不能になる問題は
  `coal_crush_at()` で塞いだが、同種の詰みを自動で見つける検査を足す
- **面エディタとの連携**: `sim` の `--stage` 出力には盤面が `grid` として入っている
  (`.`=土 空白=坑道 数字=黒ダイヤの耐久 `O`=岩 `B`=風呂 `N`=湧き出し口 `p`=火薬)。
  面データを外から与えられるようにすれば、編集ツールがそのまま採点にかけられる
