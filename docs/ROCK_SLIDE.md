## 0. 何のための仕組みか

**岩の連鎖を横方向へ広げるため。**

縦方向の伝播はすでに完全にある。**落ちる岩は、その列の黒ダイヤを割れていようが
いまいが全部貫いて採る。** だから「岩の真下に炭層がある」だけで連鎖になる。

足りないのは横。盤面を広く使う連鎖が生まれない。そこで
**「落ちてきた岩が別の岩に当たると、下の岩が横へ1升ずれる」**を入れた。
ずれた先にまた炭層があれば、そこから縦の連鎖が再発火する。

**設計の意図（外部提案より）**: 滑る向きを「左右のうち坑道がちょうど一方だけ」で
決めることで、**プレイヤーが片側だけ掘れば向きを指定できる**。
掘るという本作の唯一の動詞で、連鎖の形を決められる。

## 1. いまのルール（全文）

### 1.1 発動の入口

落ちている岩 A が、**升の境目に達した瞬間**に真下を見る。

```
真下に岩 B が居て、B が「静止」か「揺れ」の状態
    -> A は落下距離に関わらず必ず割れて消える
    -> B は条件を満たせば横へ1升滑る
```

**A が必ず消えるのは技術的な要請。** A が B の上に載って止まると、その行に別の岩が
居る可能性が出る。**MSX2 のスプライトは横一列に8枚までしか出ず、9枚目以降は消える**ので、
岩は「1行に1個まで」で配置している。A が消えれば動くのは B だけで、B は自分の行の中を
横へ動くから、この制約が絶対に壊れない。

### 1.2 滑る向き

B の左右を見る。

| B の左右 | 結果 |
|---|---|
| **片側だけ坑道** | **その方向へ1升滑る**（左右どちらでも） |
| 両方とも坑道 | 滑らない |
| 両方とも土 | 滑らない |
| 両方とも塞がり（黒ダイヤ・岩・場外） | 滑らない |

**土は「塞ぐ」扱い。** これがプレイヤーの操作の入口になっている。

### 1.3 滑ったあと

1升ぶん（`ROCK_SLIDE_SPD` 2px/frame × 8フレーム）横へ動き、
**`ROCK_JIG_PUSH` 6フレーム揺れてから**落ち始める。
落ち始めたら真下が坑道か黒ダイヤである限り落ち続ける。

## 2. なぜ発動しないのか（測定）

### 2.1 実際の面での発動率

全15面で落盤（炭柱を壊す）を起こして数えた。

```
岩が岩に乗る場面: 10 回
  左右とも土や岩で塞がり  9 回  <- 滑らない
  左右とも坑道            0 回  <- 滑らない
  片側だけ坑道            1 回  <- 滑る
```

**15面ぜんぶで1回。** しかもその1回は滑った先に炭層が無く、何も起きなかった。

**岩は土の中に埋まっているので、左右も土。** 設計意図どおり「プレイヤーが片側を掘る」
必要があるが、**そこへさらに別の岩を落とす**という二重の仕込みが要るため、
遊んでいて偶然起きることがない。**規則の存在に気づけない。**

### 2.2 そもそも「岩が岩に乗る」条件が異常に狭い

落盤で岩がどう動くかは、真下によって2つに分かれる。

| 岩の真下 | どうなるか |
|---|---|
| **黒ダイヤ** | その黒ダイヤが割れる。支えを失って**普通に落ちる** |
| **土** | 炭柱に書かれた**沈み込みブロック数だけ沈む**。**沈んでいる間は下に何があっても素通りする（岩の上も通過する）** |

そして**落ち始める順番は上の行から**。揺れの長さが
`ROCK_JIG_FRAMES 45 + 行番号 × CAVEIN_ROW_DELAY 10` フレーム。
**X 座標は一切関係しない。**

1升落ちるのに8フレームかかるので、**1行違えば10フレームずれ、上の岩は下の岩が
動き出す前に沈み終わる**。つまり当たり判定は**下の岩の「元の行」**に対して行われる。
上は「元の行 ＋ 沈み込み」で止まるので、

> ### **行の差 ＝ 沈み込みブロック数 ＋ 1**

実測（下の岩の右だけ坑道にして全組み合わせ）:

```
            行の差  1    2    3    4    5
  沈み込み1:      -   滑る   -    -    -
  沈み込み2:      -    -   滑る   -    -
  沈み込み3:      -    -    -   滑る   -
```

**沈み込みの値ごとに、ぴったり1通りしか無い。**

さらに、**沈み込みブロック数は炭柱ごとに違う**（升の左下に数字が出ている。1〜3）。
面には炭柱が最大2本（`PILLAR_MAX`）あるので、**どちらを壊すかで結果が変わる**。

### 2.3 まとめると、発動には次の全部が同時に要る

1. 同じ列に岩が2つある
2. その2つの**行の差が「壊す炭柱の沈み込み ＋ 1」ちょうど**
3. 下の岩の**左右のうち片方だけが坑道**（＝プレイヤーが掘ってある）
4. （意味を持たせるなら）滑った先の列に**炭層がある**

**4つ全部が揃う確率が、実測で15面に1回。**

| | 状態 |
|---|---|

仮に発動しても、プレイヤーは気づかない可能性が高い。

## 4. 変えられるもの・変えられないもの

### 4.1 安く変えられる

| | いま | 備考 |
|---|---|---|
| `ROCK_SLIDE_SPD` | 2 px/frame | 滑る速さ |
| `ROCK_JIG_PUSH` | 6 フレーム | 滑ったあとの予兆 |
| `CAVEIN_ROW_DELAY` | 10 フレーム | 落盤で1行あたりずらす量。**ここが行の差の条件を決めている** |
| `ROCK_JIG_FRAMES` | 45 フレーム | 落盤の揺れ |
| 滑る向きの決め方 | 「片側だけ坑道」 | `slide_start()` の数行 |
| 沈み込み中に岩を見るか | **見ない（素通り）** | `rock_fall_step()` の早期 return |

### 4.2 変えにくい／変えられない

- **「1行に1個まで」の岩の配置**。MSX2 のスプライトが横一列8枚までのため。
  **上の岩を必ず消しているのはこの制約に由来する**（§1.1）
- **岩の総数** `ROCK_MAX` 8。スプライト面は32枚中22枚使用（自機1・爆弾1・岩8・敵6・かけら6）
- **落下速度** `ROCK_FALL_SPD` 2px/frame（1升8フレーム）。これを変えると
  行の差の条件も落下の手触りも同時に変わる

### 4.3 予算

| 置き場 | 空き |
|---|---|
| 固定領域 0x4000-0x9FFF（24KB） | **2150 バイト**（`rock.c` はここ） |
| バンク窓 0xA000-0xBFFF（8KB） | 1600 バイト |
| RAM 実行 0xD000-0xEDFF（7.5KB） | 2542 バイト（`enemy.c` はここ） |

**速度の制約**: ボトルネックは CPU ではなく **VDP への書き込み**。
掘っている間で 55fps。**パレット操作・画面揺れ（R#18）・PSG・スプライトの座標移動は
ほぼ無料**、背景への描き足しは高い。

## 5. 実装側で考えている案（再提案は不要）

| | 案 | 効果の見込み |
|---|---|---|
| A | **両方が同じとき（両方土／両方坑道）は、自機から遠い側へ滑らせる** | 必ず滑るので規則に気づける。「片側だけ掘る」という精密な指定は上位のまま残る。**自分の立ち位置がその場の操作になる** |
| B | **沈み込み中も岩との接触を見る**（いまは素通り） | 「行の差＝沈み込み＋1」というぴったり条件が消え、当たれば滑るようになる |
| C | 滑りに音を付ける | いま無音。`SFX_CLICK`（岩を押して升の境目を越えたときの「カチッ」）が流用できる |

## 6. 相談したいこと

**この規則を、もっと単純明快で爽快なものにしたい。**

いまの状態は次のように整理できる。

- **仕組み自体は動いている**（面1で実際に起き、滑った岩が炭層を貫いて連鎖3まで伸びる）
- **条件が狭すぎて出会えない**（15面に1回）
- **出会っても伝わらない**（音も専用の絵も無い）

とくに聞きたい点:

1. **「片側だけ坑道」という向きの決め方は妥当か。** プレイヤーが掘って指定できるのは
   良いが、素のままだと両側とも土で死んでいる。**もっと単純で、かつプレイヤーの
   意図が入る決め方**はないか
2. **「行の差＝沈み込み＋1」を解消すべきか。** §5-B で消せるが、そうすると
   「落盤したら岩が次々ぶつかって滑る」になり、**制御できない現象**になる恐れがある
3. **爽快感をどこで出すか。** 滑りは 0.13秒の横移動でしかない。
   音・揺れ・パレットは安く使える（§4.3）
4. **そもそも横滑りが最適解か。** 「岩の連鎖を横へ広げる」という目的に対して、
   別の仕組み（例: 落ちた岩が割れて破片が横へ飛ぶ、など）のほうが単純ではないか

**§4.2 の制約（1行1個・スプライト8枚/行）は動かせない**ので、そこを踏まえた案がほしい。
